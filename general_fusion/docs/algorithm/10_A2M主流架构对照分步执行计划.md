> 执行记录：[A2M 评审记录](11_A2M评审记录.md)

## 1. Context：当前证据与缺口

### 1.1 已有结论

A1 在三个完整传感器、固定温压和 `T=1` 稳态观测上完成了 Ridge、GBDT、简单拼接 MLP 与后融合基线。固定拼接 MLP（B5）明显优于 Ridge 和 GBDT，并成为当前主要强基线。

A2 与 A2H 继续比较了 Torch concat、输出闭合头、Deep Sets 和 grouped OOF residual。A2 没有候选进入 formal test；A2H 在 calibration、environment、joint、noise 四个合格困难轴上仍未找到稳定超过 B5 的 C1 或 M1，最终冻结 B5 并以负结果关闭。

这些结果支持“当前已运行候选没有稳定超过简单 MLP”，但不能支持“B5 已在主流深度学习架构中胜出”。当前正式主线缺少同一数据、split、输入、训练预算和测试锁下的 MLP、表格残差网络与注意力表格模型对照。

### 1.2 当前必须先解决的问题

当前全量测试中，A1 保存的 B5 指标与共享 evaluator 重算值存在回归不一致。A1 的 B5 使用 scikit-learn `MLPRegressor`，A2/A2H 的 B5-like 使用 PyTorch `TorchConcatMLP`；二者拓扑接近，但训练器、目标缩放、early stopping 和运行时依赖不同，不能只用同一个“B5”名称掩盖实现差异。

A2M-0 未通过前，不允许启动架构排名。修复不得通过放宽到失去约束意义的容差、删除失败测试、重写冻结 A1 summary 或选择性忽略不一致实现。

### 1.3 输入适用性边界

A1 与 A2H 每个传感器只有一个稳态标量，`T=1, F=1`。因此：

- MLP、Tabular ResNet 和 feature-token Transformer 适用于 A2M 正式比较；
- 1D CNN、TCN、GRU/LSTM 和时序 Transformer 没有可用时间维，A2M 不运行、不排名；
- 时序架构矩阵在 A2M 关闭时冻结，由保留真实时间维的 A3 xylene 数据执行；
- 不把三个异构传感器的固定排列伪装成平移等变时间轴或空间网格。

## 2. Task：研究问题、范围与不变量

### 2.1 研究问题

A2M 只回答三个问题：

1. A1 的 B5 强结果能否在明确运行时指纹下复现？
2. 在相同稳态输入和公平预算下，Tabular ResNet 或轻量 FT-Transformer 是否稳定优于统一 PyTorch MLP？
3. 若没有非 MLP 架构晋级，是否可以把 MLP 冻结为 A3 的完整输入参考，而不再声称它是未经对照的“最佳深度算法”？

### 2.2 不在本阶段回答

- 不评价时序卷积、循环网络或时序 Transformer；
- 不评价传感器缺失、未见组合、质量门控和可靠性路由；这些属于 A4；
- 不评价零样本跨数据集迁移；
- 不引入大型 Transformer、MoE、生成式补全、外部预训练 TabPFN 或无上限超参数搜索；
- 不重新打开 A2 已关闭的 Deep Sets、输出头或 residual 候选；
- 不把仿真排名写成真实 TraceGas 硬件结论。

### 2.3 延续的不变量

1. `mixture_id` 是唯一 group key，不回退或重写为 `sequence_id`。
2. 数据、模型和评价不依赖 `base_condition_id`、`noise_seed_index` 或 `noise_seed`。
3. scaler、缺失统计和阈值只由训练组拟合。
4. A1 formal v1 与 A2H v2 保持只读；新结果使用 A2M 独立 schema、配置和输出目录。
5. 所有架构共享目标、输入可见字段、评价器、seed 集和 split 访问规则。
6. 失败运行、非有限 loss、checkpoint 缺失或 test 未授权访问必须显式失败，不从均值中静默删除。

## 3. Format：模型、数据与交付格式

### 3.1 正式模型矩阵

| ID | 角色 | 架构 | 输入 | 正式处置 |
| --- | --- | --- | --- | --- |
| B3 | 传统低容量基线 | 全输入 Ridge | 三路标准化稳态标量 | 复用唯一基线实现 |
| B4 | 传统强树基线 | 全输入 GBDT | 三路标准化稳态标量 | 复用唯一基线实现 |
| B5-SK | 历史深度参照 | scikit-learn 单隐层 MLP | 三路标准化稳态标量 | 只读复现与身份审计，不作为新训练器公平比较的主基线 |
| A2M-MLP | 主强基线 | PyTorch concat MLP | 三路标准化稳态标量 | 新架构比较的唯一主基线 |
| A2M-RESNET | 主流候选 | 小型 Tabular ResNet | 与 A2M-MLP 完全相同 | 固定两档容量 |
| A2M-FTT | 主流候选 | 轻量 FT-Transformer | 三个带传感器身份的 feature token | 固定两档容量，不使用时间位置编码 |

A2 的 C1/M1 和 A2H 的 C1/M1 只作为历史机制对照进入报告，不在 A2M 重新训练或改名。A2M-FTT 使用传感器 ID 或类型 token 与 class token，但不读取数据集名称、真实标定 profile、hard-test 环境真值或目标标签派生信息。

### 3.2 容量与训练预算

每个深度架构只允许两个预注册 recipe：

| 架构 | recipe 1 | recipe 2 | recipe 上限 |
| --- | --- | --- | --- |
| A2M-MLP | 1 个隐藏层、宽度 32、LBFGS | 1 个隐藏层、宽度 32、AdamW | 只比较优化器 recipe，不同时搜索深度和宽度 |
| A2M-RESNET | 宽度 16，2 个 residual block | 宽度 32，2 个 residual block | 两个 recipe 都使用冻结 AdamW 配置 |
| A2M-FTT | token dim 8，1 个 encoder block，2 heads | token dim 16，1 个 encoder block，2 heads | 两个 recipe 都使用冻结 AdamW 配置 |

约束：

1. 每个架构恰好两个 recipe，不允许看到 val 后增加第三档。
2. 每个 recipe 使用 seed `17, 29, 43, 71, 101`，失败 seed 不得删除。
3. 所有模型使用同一 normalized MSE、H0 独立回归头、train-only scaler 和 early-stopping 指标。
4. primary arm 不读取温度和压力；统一上下文 arm 只在主模型配置冻结后做 matched 诊断，不参与架构选择。
5. recipe-level 排名允许预注册的模型适配优化器，但每个架构搜索次数相同。若非 MLP 获得晋级资格，必须补做同优化器、相近参数量 MLP 对照，才能把收益归因于架构而非训练器。
6. 参数量不要求所有 recipe 强行相等，但必须报告；机制归因对照的参数量相对差必须不超过 10%。

### 3.3 数据与 test 锁

A2M 开发期只读取 A2H v2 的 `train`、`val` 和四个合格轴的 `stress_val`。A1 test 与 A2H hard-test 已经公开，只能作为历史数值参照，不参与 A2M 训练、早停、recipe 选择、架构排序或门槛调整。

A2M 新建独立 formal holdout：

| 项目 | 冻结要求 |
| --- | --- |
| schema | `gf-a2m-data-1` |
| data version | A2M-1 生成时登记为 `gf-a2m-v1-<freeze-date>-r1` |
| group key | `mixture_id` |
| 组成与观测 | 新 `mixture_id`，不得复制 A1/A2H test group |
| 轴 | iid、calibration、environment、joint、noise；composition 只作诊断，不参与晋级 |
| 生成器 | 复用 `src/gf/sim/ar_he_co2.py` 与 A2H 已冻结扰动语义，不复制物理方程 |
| 访问 | 模型、recipe、seed、checkpoint 与图表模板全部冻结后一次解锁 |
| 证据 | content hash、split hash、profile hash、配置 hash、checkpoint hash、runtime fingerprint |

formal holdout 的配置和全部 hash 在开发比较前生成并登记；训练入口没有读取 test 标签的代码路径。若 holdout 规格需要修改，必须升版并使旧版本保持只读，不能覆盖重生成。

### 3.4 指标与结果表

每个架构、recipe、seed 和困难轴必须报告：

- `macro_RNMAE`；
- Ar、He、CO₂ 的 RNMAE 与 mol% MAE；
- RMSE、R²、P90 group MAE 和 worst-group MAE；
- 配对 `mixture_id` bootstrap 的误差差与 95% CI；
- 参数量、训练时间、单样本推理时间和峰值显存；
- best epoch、实际 epoch 数、checkpoint hash 和运行时指纹；
- 非有限 loss、失败 seed、物理越界与组成和偏差。

五模型预测均值可作为次级部署对照，但不能替代五个独立 seed 的稳定性门。

## 4. 决策规则

### 4.1 开发集架构晋级门

非 MLP 架构相对 A2M-MLP 必须同时满足：

1. iid `macro_RNMAE` 相对 A2M-MLP 的平均退化不超过 5%；
2. 在 calibration、environment、joint、noise 中至少两个轴平均相对改善不少于 5%；
3. 对满足第 2 条的每个轴，至少 4 / 5 seed 改善方向一致；
4. 对满足第 2 条的每个轴，配对 group bootstrap 95% CI 上界严格小于 0；
5. 任一晋级轴、任一组分的 RNMAE 绝对退化不超过 `0.005`；
6. 补做的同优化器、参数匹配 MLP 对照不能解释全部收益。

若多个非 MLP 架构通过，开发集选择顺序固定为：通过轴数量更多 → 最差合格轴改善更大 → 参数量更少。此顺序只在 formal 解锁前使用，formal 结果不触发重新选择。

### 4.2 formal 确认

A2M formal 一次同时评价每个架构在开发集选出的唯一 recipe 和五个 seed。formal 只确认开发集选择，不再调参。非 MLP 架构只有在 formal 上继续满足 iid 非劣化、至少两个轴 4 / 5 seed 同向、CI 和组分退化门时，才可替换 A2M-MLP。

### 4.3 允许的终态

| 终态 | 条件 | A3 交接 |
| --- | --- | --- |
| `POSITIVE_RESULT` | 一个非 MLP 架构通过开发与 formal 全部门 | 冻结该架构为完整输入参考，A2M-MLP 保留为主基线 |
| `MLP_RETAINED` | 非 MLP 架构均未通过，或 formal 未确认开发收益 | 冻结 A2M-MLP；负结果视为完成，不扩大候选池 |
| `NO_STABLE_DIFFERENCE` | 各主轴平均相对差异均在 ±5% 内、配对 CI 均跨 0，且无架构通过晋级门 | 按简约性冻结 A2M-MLP，并明确 benchmark 不支持架构优越性声明 |
| `INVALID` | 复现、数据、split、test 锁或评价契约失败 | 不生成排名，不进入 A3 模型冻结 |

## 5. 分步执行

### A2M-0：基线复现与模型身份冻结（1–2 天）

目标：解释当前 A1 指标回归失败，建立可追踪的 B5 身份与运行时事实源。

实施：

1. 在隔离用户 site-package 的环境下运行全量测试和 A1 指标回归。
2. 对保存的 `baseline_summary.json`、predictions、manifest、evaluator 输入和当前重算结果逐项核对。
3. 记录 Python、NumPy、SciPy、scikit-learn、PyTorch、BLAS、device、dtype 和确定性设置。
4. 将历史 B5 明确登记为 B5-SK，将 PyTorch 主基线登记为 A2M-MLP；配置、checkpoint 和结果不得共用同一模型身份。
5. 若差异来自代码回归，修复唯一评价或预处理实现；若来自依赖数值漂移，冻结可复现环境并建立新 A2M reference，不覆盖 A1 v1。
6. 新增自动回归测试，证明保存预测经共享 evaluator 重算一致。

阶段门：根因明确；冻结 A1 文件未改写；全量测试通过；运行时指纹可机器读取。任一条件失败则 A2M 停止为 `INVALID`。

### A2M-1：冻结协议、holdout 与模型矩阵（1–2 天）

目标：在任何新架构训练前冻结数据访问、模型预算、晋级门和 formal test 锁。

实施：

1. 新建 `configs/data/ar_he_co2_a2m_v1.json`，只登记 A2H 开发来源与独立 formal holdout 规格。
2. 新建 `configs/eval/a2m_eval.json`，冻结轴、指标、五 seed、bootstrap、等价带和晋级门。
3. 新建 `configs/train/a2m_train.json`，冻结每架构两个 recipe、early stopping 和训练预算。
4. 新建 `configs/experiment/a2m_protocol.json`、`a2m_dev.json`、`a2m_formal.json` 和主图表模板。
5. 生成并哈希 A2M formal holdout；训练入口只能看到 split 标识和不含 test 标签的 manifest 元数据。
6. 用协议测试证明 A1 test、A2H hard-test 和 A2M formal 未授权读取均显式失败。

阶段门：配置 hash、holdout hash、允许 split、模型矩阵和所有判定阈值在模型结果前冻结。

### A2M-2：实现主流架构与统一注册表（2–3 天）

目标：在一个配置驱动的模型注册表中实现 A2M-MLP、A2M-RESNET 和 A2M-FTT，不产生数据集专属训练分支。

实施：

1. 新建 `src/gf/dl/mainstream_architectures.py`，只负责三类模型定义和配置校验。
2. A2M-MLP 使用固定顺序标量拼接；A2M-RESNET 使用输入投影、两个 residual block 和公共 H0 head。
3. A2M-FTT 将每个传感器标量与 `sensor_id`、`sensor_type` 编码为 feature token，引入 class token；不使用时间位置编码。
4. 复用现有训练、评价、scaler 与 checkpoint 逻辑；公共逻辑缺失时修改唯一实现，不在 A2M pipeline 复制。
5. 增加 shape、mask、有限输出、梯度、模型构建、参数量和未知配置失败测试。
6. 增加输入语义测试：`T=1` 配置请求时序模型必须明确拒绝，不能自动展平后冒充时序比较。

阶段门：三个模型均通过 forward/backward 和 checkpoint round-trip；模型定义不读取 dataset 名称或 test 元数据；参数量与 recipe 配置一致。

### A2M-3：训练协议 smoke 与预算校准（1–2 天）

目标：证明所有 recipe 能在相同小样本协议下完成训练，并冻结正式运行预算。

实施：

1. 在只含 train/val 的小样本上执行每架构每 recipe 单 seed smoke。
2. 检查 loss 有限、验证指标可计算、early stopping 生效、checkpoint 可加载和重复 seed 可复现。
3. 记录参数量、epoch 时间、峰值内存和完整训练预计成本。
4. 只允许修复工程错误或明显无效的配置语法；不得根据模型排名修改容量、学习率或 patience。
5. 输出 `a2m_smoke.json` 与预算审计；formal holdout 保持锁定。

阶段门：六个 recipe 全部可执行；没有静默失败或缺失 seed；正式训练预算和并行度冻结。

### A2M-4：开发集主流架构比较（4–6 天）

目标：在 iid val 和四个合格 stress-val 轴上完成有界架构筛选。

实施：

1. 运行 3 个架构 × 2 个 recipe × 5 个 seed，共 30 个主训练运行。
2. 同步重跑 B3、B4；B5-SK 只报告复现身份，不参与 PyTorch recipe 排名。
3. 逐轴生成 seed 表、组分表、最差组、bootstrap、资源与失败案例。
4. 每个架构只按冻结规则选择一个 recipe；不得按不同轴选择不同 recipe 拼成赢家。
5. 非 MLP 达到开发晋级门时，执行同优化器、参数匹配 MLP 审计。
6. 冻结每个架构的唯一 recipe、五个 checkpoint、排序、候选状态和图表模板。

阶段门：30 个主运行及触发的 matched audit 证据完整；模型选择未读取任何 formal 标签；每个架构只保留一个 formal 配置。

### A2M-5：一次 formal 对照与统计确认（2–3 天）

目标：在独立 holdout 上一次同时评价冻结的三类架构，形成最终架构结论。

实施：

1. 校验 data、split、runtime、config、checkpoint 与图表模板 hash。
2. 将 `formal_run_status` 置为 `FROZEN` 后一次解锁 A2M formal holdout。
3. 同时评价 A2M-MLP、A2M-RESNET 和 A2M-FTT 的冻结 recipe 与五个 seed。
4. 对每个轴执行 2000 次 `mixture_id` 配对 bootstrap；报告 iid、四个合格轴和 composition 诊断。
5. 按 §4 生成唯一终态；formal 结果不得回流 recipe、epoch、seed、数据范围或门槛。

阶段门：formal 无调参回流；每个架构、seed 和轴均有完整结果或显式失败；终态可由机器可读 summary 重算。

### A2M-6：评审关闭与 A3 交接（1–2 天）

目标：冻结完整输入参考模型，并把时序架构比较转交给具备真实时间维的 A3。

实施：

1. 新建 `docs/algorithm/11_A2M评审记录.md`，登记终态、适用范围、失败模型和不可声明内容。
2. 将正式结果追加到 `08_算法实验结果记录.md`；Idea 文档不重复登记结果。
3. 更新总体规划和 README 的阶段状态及证据链接。
4. 冻结 A3 完整输入参考模型；无非 MLP 赢家时固定 A2M-MLP。
5. 为 A3 冻结以下时序矩阵，但不在 A2M 运行：统计特征 MLP、轻量 TCN、单层 GRU、轻量 temporal Transformer。
6. A3 四类模型必须共享完整工作簿 split、原始时间 mask、训练预算和 test 锁；A3 结果不得回写 A2M 稳态排名。

阶段门：A2M 评审、结果索引、配置、summary 和 A3 交接矩阵互相一致；总体规划将下一阶段更新为 A3。

| 传统基线 | 复用 `src/gf/ml/baselines.py` | B3、B4，不复制实现 |

| 报告产物 | `outputs/reports/a2m/` | A2M 正式报告和图表 |

任何 A2M 代码不得复制物理方程、split、scaler 或 metric。若共享能力不足，应修改唯一所有者并让 A1/A2/A2H 回归测试继续通过。

## 8. 停止规则与禁止事项

| 触发条件 | 处置 |
| --- | --- |
| A1 指标回归无法解释 | A2M 关闭为 `INVALID`，不运行架构排名 |
| formal holdout 在冻结前被用于模型选择 | 结果作废，升版 holdout 和协议 |
| 任一架构获得额外 recipe 或 seed | 公平比较作废，全部架构按统一预算重新执行 |
| 非 MLP 收益仅来自优化器或参数量 | 不声明架构优势，保留 recipe-level 结果 |
| 所有主轴差异均在 ±5% 且配对 CI 跨 0 | 关闭为 `NO_STABLE_DIFFERENCE`，保留 MLP |
| 非 MLP 只在一个轴改善 | 记录条件性现象，不替换主基线 |
| `T=1` 被扩展或复制成伪序列 | 结果作废；时序比较移交 A3 |
| 需要外部预训练或新增重依赖 | 另立协议，不进入当前 A2M 主矩阵 |
| formal 后希望增加模型或改门 | 拒绝；记录为未来 Idea，不修改 A2M 终态 |

## 9. 完成定义

A2M 完成不等于必须找到比 MLP 更复杂的赢家。完成必须同时具备：

1. 可解释且通过测试的 A1/B5 复现结论；
2. 一个独立、锁定、可追溯的 A2M formal holdout；
3. B3、B4、B5-SK、A2M-MLP、A2M-RESNET、A2M-FTT 的职责清晰且结果完整；
4. 每架构相同 recipe 数、相同 seed 数和一次 formal 对照；
5. 逐轴、逐组分、bootstrap 与资源证据；
6. `POSITIVE_RESULT`、`MLP_RETAINED`、`NO_STABLE_DIFFERENCE` 或 `INVALID` 的唯一终态；
7. 一个冻结的 A3 完整输入参考模型和一组不在 `T=1` 上执行的 A3 时序架构矩阵。

只有完成以上证据链，项目才可以把 A1–A2M 描述为“已完成适用主流深度学习架构筛选”；否则只能描述为“已找到强 MLP 基线并关闭部分融合机制”。
