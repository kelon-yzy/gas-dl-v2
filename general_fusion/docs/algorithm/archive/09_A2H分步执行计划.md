## 0. 文档职责与研究问题

本文件把总体规划中的 A2H 拆成可编码、可验证、可杀停的实施步骤。A2H 的正式状态、阶段转换和近期动作仍由《项目总体规划》维护；算法数值与横向结论追加到《算法实验结果记录》，不在本文件维护第二套结果。

A2H 冻结回答四个问题：

1. A1/A2 的低误差有多少来自二维组成空间被少量训练样本充分覆盖？
2. 在独立重复、噪声放大和批次共同扰动下，模型误差何时接近可达噪声下限？
3. 温压、标定、物理参数或组成区域改变后，当前强基线还能否泛化？
4. 在困难但仍可辨识的条件下，输出约束或集合融合是否获得稳定、可归因的收益？

核心判断：**A2H 先证明 benchmark 具有可学习的困难度，再重新比较算法。困难度不合格时不开放更大网络；算法没有稳定收益时保留强基线并关闭阶段。**

## 1. Context：A1/A2 起点与问题边界

### 1.1 已冻结事实

| 事实 | 当前证据 | A2H 约束 |
| --- | --- | --- |
| A1 数据 | `gf-a1-v1-20260827-r1`，1200 个唯一 `mixture_id`，840 / 180 / 180 split | A1 v1 只读；A2H 必须新建数据版本、schema 和 manifest |
| 任务自由度 | Ar、He、CO₂ 总量闭合到 100 mol%，实际只有两个自由度 | 样本量必须结合二维空间覆盖解释，不以绝对行数判断大小 |
| 可辨识性 | 内部 Jacobian full-rank fraction 为 1，P95 condition number 为 95.706 | 困难实验不能通过破坏基本可辨识性制造高误差 |
| 当前工况 | 温度 298.15 K、压力 101325 Pa、每配方单次稳态观测 | A2H 重点增加重复观测、环境块和模型失配 |
| 当前噪声 | ToF 和热导相对动态范围噪声很小；NDIR 动态范围 / 噪声尺度约 154 | 噪声压力必须分传感器登记，不能只乘一个无物理语义的总噪声 |
| 当前强基线 | A1 B5 五 seed val `0.00581589 ± 0.00103384`；预测集成 val `0.00437865` | B5 独立 seed 是主强基线；集成只作次级部署对照 |
| A2 结论 | H1/H2 未过 seed 稳定性门，M1 未超过 C1，B5 OOF residual 不可预测 | 不自动开放 Set Transformer、residual MLP、DeepGBM 或 ErrorNet |
| A2 test | formal test 未解锁 | A2H 不读取或补跑 A2 test；建立独立 hard test |

### 1.2 A2H 不负责的内容

- 不修改 A1 v1 的配方、信号、split、hash 或已有结果。
- 不训练传感器缺失组合，不测试未见传感器集合，不声称质量自适应；这些属于 A4。
- 不引入时序任务；独立重复仍是 `T=1` 稳态观测，不重写为 `sequence_id`。
- 不把仿真扰动称为真实硬件误差分布；无硬件依据的范围只能标为 sensitivity tier。
- 不以增加样本数、网络容量或候选数量本身作为研究贡献。

## 2. Task：冻结数据、身份与访问契约

### 2.1 数据版本与 schema

当前正式数据契约为 `gf-a2h-data-2`，数据版本为 `gf-a2h-v2-20260828-r1`。A2H 不覆盖 `data/a1_formal/`，正式数据写入 `data/a2h_v2/`；此前未通过契约的 v1 运行仅保留在 archive，不作为当前证据。

每条记录至少表达：

| 字段 | 语义 | 约束 |
| --- | --- | --- |
| `mixture_id` | 配方身份和唯一 group key | 所有重复观测只能进入同一 split；不得替换为其他主键 |
| `observation_id` | 同一配方下单次稳态观测的行级身份 | 只用于追踪，不参与 split 或 bootstrap 主单位 |
| `environment_id` | 温压环境块 | 只用于上下文与分层，不替代 `mixture_id` |
| `calibration_profile_id` | 零点、增益、光程和响应参数组合 | 只用于批次与失配分层；候选不得读取 test 真值参数 |
| `condition_family` | pure、binary 或 ternary | 三类必须分别报告；A1 中不存在的 pure 在 A2H 新版本中显式加入 |
| `signals` | 三路完整稳态观测 | A2H 始终三路可用，`quality=1`、无 missing |
| `target` | 三组分 mol% | 非负且总和为 100 |

不同观测实现的随机状态只登记在数据配置或运行 manifest。数据、模型和评价不得生成或依赖 `base_condition_id`、`noise_seed_index`、`noise_seed`；所有重复观测仍以 `mixture_id` 分组。

### 2.2 split 族

A2H 不用一套随机 split 同时回答所有问题，而是冻结互相独立的 split 族：

| split 族 | train | val / stress-val | hard test | 用途 |
| --- | --- | --- | --- | --- |
| `iid` | 名义工况、随机组成组 | 同分布独立组 | 同分布独立组 | 与 A1 对齐并建立新生成器基准 |
| `noise` | 1× 名义噪声 | 2×、5× 预注册档 | 10×及冻结相关 / 批次扰动 | 噪声响应曲线 |
| `environment` | 训练温压块 | 相邻但不重叠温压块 | 远端冻结温压块 | 环境 OOD |
| `calibration` | 名义标定 profile | 轻度零点 / 增益 / 光程失配 | 冻结中度失配组合 | 标定和物理模型失配 |
| `composition` | 指定单纯形区域 | 相邻浓度带或边界 | 整块留出浓度带、纯气或边界族 | 组成 OOD 与结构零 |
| `joint` | 通过资格审计的单因素 train | 冻结单因素组合 stress-val | 两项以上冻结组合 | 最终联合压力 |

所有 split 族都必须保持 train、val、test 的 `mixture_id` 交集为空。环境 split 使用组成分布匹配但配方 ID 互斥的组，不能让同一标签配方跨环境泄漏到 test。

### 2.3 上下文可见性

温度和压力可能是可部署输入，也可能是未知扰动。H-ENV 固定两个 matched 臂：

- `ENV-C0`：模型不读取温压，只测试对未知环境变化的鲁棒性；
- `ENV-C1`：所有算法都读取相同、由 train 拟合 scaler 的温压上下文，测试已知环境下的函数泛化。

`ENV-C1 - ENV-C0` 只解释为环境上下文信息增益，不归因于融合核心。真实标定偏差和物性参数只允许特权 oracle 读取，不进入候选模型输入。

### 2.4 test 锁

开发期允许读取 `train`、`inner_oof`、`val` 和 `stress_val`；所有 `hard_test` 默认锁定。最终解锁至少校验：

- data content hash 与 split-family hash；
- 合格困难轴及档位清单 hash；
- 候选配置与 matched baseline 配置 hash；
- selected checkpoint hash；
- 主图表模板 hash；
- formal run status=`FROZEN`。

缺任一证据即显式失败，不生成部分 hard-test 结果。

## 3. 难度定义与资格审计

### 3.1 三类参照

每个困难轴都同时运行三个参照：

1. **最近邻覆盖基线**：量化训练配方密度本身能达到的误差；
2. **特权数值反演 oracle**：使用生成该观测的真实温压和物理 / 标定参数，估计仍可辨识条件下的噪声下限；
3. **冻结 concat 强基线**：使用 A2H train / val 重训的 B5-like 或 matched Torch concat，量化实际学习器误差。

oracle 只用于难度资格和误差分解，不参与候选排序，也不得作为可部署结果。

### 3.2 合格困难轴

困难轴及档位必须先由物理来源或固定 sensitivity tier 生成，再仅用 oracle、最近邻和冻结 concat 在 `stress_val` 上做资格审计。默认资格门为：

1. 内部样本 Jacobian full-rank fraction `>=0.99`；纯气和结构零边界单列，不混入该分母。
2. Jacobian condition number P95 `<1000`，并报告最大值与最差方向。
3. 冻结 concat 相对同算法 `iid val` 的 macro_RNMAE 退化至少 `25%`。
4. 特权 oracle 相对冻结 concat 至少保留 `20%` 的误差改善空间。
5. 三路信号仍在预注册物理边界内；越界档位直接判为不合格，不靠裁剪进入。

至少两个相互独立的困难轴通过以上资格门，A2H 才允许进入算法比较。若所有档位都被 oracle 同样击穿，说明场景不可辨识或物理范围不合格，应缩回扰动范围；若 concat 与 oracle 始终等价，说明 benchmark 仍饱和，应关闭 A2H 算法搜索。

### 3.3 指标

除 A2 的 `macro_RNMAE` 外，A2H 必报：

- 各组分 mol% MAE、RMSE、R²；
- P90 group MAE、worst-group MAE；
- 各环境、标定 profile、组成区域和噪声档位的分层结果；
- 相对 `iid` 的退化率和相对 oracle 的 headroom；
- 非负率、越界率、组成和偏差、结构零残余预测；
- 参数量、训练时间和推理时间。

总体平均不能覆盖最差环境或关键组成区域的失败。

## 4. 高难度实验矩阵

### 4.1 H-LC：学习曲线

- 从完整 train group 构造嵌套比例 `10% / 20% / 40% / 70% / 100%`，子集只按 `mixture_id` 选择。
- 每档使用相同五个训练 seed，并保持 pure、binary、ternary 与浓度区域覆盖规则。
- 固定同一 iid val 和 iid test，不因训练规模改变 test。
- 主输出为误差—训练 group 数曲线、seed 离散度和幂律或单调趋势诊断。

判断：若少量组已进入 oracle 等价带，低误差主要由低维平滑映射与覆盖密度解释；若误差持续随样本下降，A2H 正式规模需由曲线确定，而不是沿用 1200 的方便值。

### 4.2 H-NR：独立重复与噪声压力

- 每个配方生成多个独立 `observation_id`，所有重复共享 `mixture_id` 和 split。
- 白噪声档固定为 A1 每传感器噪声尺度的 `1× / 2× / 5× / 10×`。
- 相关噪声和批次共同扰动单独配置，不与白噪声合并成一个匿名 scale。
- 报告单次观测、同配方重复均值和不做平均三种部署语义；重复均值不能替代单次主结果。

判断：区分模型逼近误差、单次观测噪声和重复平均收益。只有 train-only 重复增强改善独立 stress-val 时，才允许进入正式训练配置。

### 4.3 H-ENV：温压环境外推

- 温压档位在 A2H-0 由应用范围或 sensitivity tier 冻结，train、stress-val 和 hard-test 环境块不重叠。
- 同时运行 `ENV-C0` 和 `ENV-C1`，其他网络容量、训练预算和 split 完全一致。
- 每个温压块重新执行动态范围、饱和、Jacobian 秩和 condition number 审计。
- hard test 不得使用 val 最差环境临时替换或扩展。

判断：若 `ENV-C1` 明显优于 `ENV-C0`，温压应作为可部署上下文进入统一适配器；若两者都接近 oracle，环境变化不是剩余难点；若 oracle 同时失败，则缩回物理范围。

### 4.4 H-CAL：标定与物理模型失配

- 分传感器设置零点、增益、光程、响应系数和允许物性参数扰动；不同来源不得压缩成一个总扰动量。
- train 只见名义或预注册轻微 profile，hard test 使用未见 profile 组合。
- 候选模型不能读取 hard-test profile 真值；特权 oracle 和审计报告可以读取。
- 负对照包括只改变一个传感器、三个传感器同向漂移和方向冲突的 profile。

判断：区分模型对共同标定偏差、单传感器偏差和物理模型失配的敏感性。A2H 只报告完整输入鲁棒性，不在本阶段引入质量门控或故障抑制。

### 4.5 H-COMP：组成区域留出

- 配置化定义纯气、二元、三元、近边界、中心区和组分主导区，不根据结果临时移动浓度阈值。
- 至少包含一个浓度带整块留出、一个 simplex sector 留出和纯气 / 结构零外推。
- 同时报告几何最近训练距离，区分插值跨度与模型结构问题。
- pure 样本是 A2H 新数据，不回写 A1 的 `NA` 分层。

判断：检验固定拼接、闭合输出头和集合表示在边界、结构零及远离训练覆盖区时的差异。

### 4.6 H-JOINT：联合压力

- 只组合已经通过资格审计的单因素困难轴，每次最多引入两个主因素和一个固定噪声档。
- 联合组合在算法选择前冻结，不用单因素候选结果挑选“最有利组合”。
- 主报告按组合单列，并提供相对于对应单因素的增量退化。

判断：确认单因素收益能否在更接近应用的联合变化下保留。联合压力不通过时，不用总体平均掩盖。

## 5. 分步实现

### A2H-0：冻结协议、范围和身份契约（2–3 天）

目标：把数据 schema、split 族、扰动来源、默认资格门、算法预算和 hard-test 锁写成机器可检查配置。

实施：

1. 新建并冻结 `configs/data/ar_he_co2_a2h_v2.json`，登记组成空间、重复数、温压档、噪声档、标定 profile 和每项来源等级。
2. 新建 `configs/eval/a2h_eval.json`，登记指标、资格门、五 seed、bootstrap、晋级门和分层字段。
3. 新建 `configs/experiment/a2h_protocol.json`、`a2h_difficulty_audit.json`、`a2h_formal.json` 与主图表模板。
4. 固定 `gf-a2h-data-2`、`mixture_id` 分组和 hard-test required evidence。
5. 用协议测试证明禁止字段、split 交叉、test 未授权读取和配置漂移均显式失败。

阶段门：所有范围与阈值在生成候选结果前冻结；没有无法追踪来源的匿名扰动；A1 hash 不发生变化。

### A2H-1：实现 A2H 数据生成与 nominal parity（4–6 天）

目标：在不复制物理方程的前提下生成重复、环境和标定 profile 数据，并证明名义条件没有改变 A1 物理语义。

实施：

1. 新建 `src/gf/sim/a2h_dataset.py`，复用 `src/gf/sim/ar_he_co2.py` 的唯一物理实现，不从 `a1_dataset.py` 复制方程。
2. 新建 A2H condition、observation 和 manifest 契约；重复观测共享 `mixture_id`。
3. 将环境参数、标定 profile 和噪声档通过显式参数传入生成器；不读取全局隐藏状态。
4. 名义温压、名义 profile、1× 噪声下运行 deterministic signal parity 和分布审计。
5. 保存 content hash、split-family hash、profile hash 和生成器配置 hash。

阶段门：A1 v1 文件与 hash 不变；名义 deterministic signal 在浮点容差内一致；重复组不跨 split；三路信号 shape 和单位契约通过。

### A2H-2：实现 oracle、覆盖基线与难度资格审计（4–5 天）

目标：先区分“困难但可学”与“信号已不可辨识”，只让合格轴进入训练。

实施：

1. 新建 `src/gf/sim/a2h_audit.py`，实现分环境 Jacobian、动态范围、饱和和 condition number 审计。
2. 实现最近邻组成覆盖诊断；距离只使用 train 配方，不能读取 test 标签选择模型。
3. 实现特权数值反演 oracle，分别登记真实 profile oracle 和名义参数反演对照。
4. 用冻结 concat 在 stress-val 上运行难度资格门，生成 `eligible_axes.json`。
5. 不合格档位保留失败原因，不静默替换；范围修改必须升版协议和数据版本。

阶段门：至少两个独立困难轴通过 §3.2；否则 A2H 在本步停止，不进入算法搜索。

### A2H-3：学习曲线与噪声响应（4–5 天）

目标：量化样本覆盖、独立重复和噪声尺度对低误差的贡献。

实施：

1. 在嵌套训练组上运行 B3、B4 和冻结 concat 五 seed 学习曲线。
2. 在 1×、2×、5×、10× 与合格相关噪声档上运行单次观测主结果。
3. 对同配方重复均值做只读部署对照，不参与主候选选择。
4. 输出误差—样本量、误差—噪声、oracle gap 和 seed 离散度曲线。

阶段门：能明确区分覆盖误差与噪声误差；曲线不使用 hard test 调整训练规模或噪声档。

### A2H-4：温压与标定 OOD（5–7 天）

目标：在完整传感器下评价环境上下文和模型失配，而不引入 A4 可靠性机制。

实施：

1. 运行 `ENV-C0 / ENV-C1` matched 对照；环境训练块使用三个独立温压点，并由 train-only context scaler 标准化。
2. 运行单传感器标定偏差、共同漂移和冲突 profile。
3. 报告每个环境和 profile 的强基线、oracle、最差组和组成分层。
4. 只用 stress-val 决定哪些合格轴进入算法比较，hard test 保持锁定。

阶段门：困难来源可归因到环境未知、上下文缺失或模型失配之一；不可辨识档位不进入后续。

### A2H-5：组成区域留出与结构零（4–5 天）

目标：验证算法在远离训练覆盖、纯气和结构零边界上的行为。

实施：

1. 生成并冻结 concentration-band、simplex-sector 和 pure / binary boundary split。
2. 运行 B3、B4、冻结 concat、H0 和 H1；H2 单列结构零残余，不与严格零头混为一类。
3. H3 sparsemax 只有在 H2 的结构零失败已由 stress-val 触发且配置预注册后才开放一次 matched 诊断。
4. 输出几何最近距离、逐边界类型误差、负值率、闭合误差和零组分残余。

阶段门：组成 OOD 的误差能与覆盖距离和输出头语义对应；不以添加伪计数修补结构零。

### A2H-6：合格困难轴上的 matched 算法比较（5–7 天）

目标：只在已证明具有 headroom 的 stress-val 上重新检验融合机制。

固定矩阵：

| 角色 | 算法 | 用途 |
| --- | --- | --- |
| 低容量基线 | B3 Ridge | 检查线性可解程度 |
| 强树基线 | B4 GBDT | 检查分段非线性与样本覆盖 |
| 主强基线 | B5-like raw scalar concat | 冻结强参考 |
| 参数匹配对照 | C1 ordered concat + 选定公共 head | 隔离训练器和容量 |
| 集合候选 | M1 token + Deep Sets + 同一公共 head | 检验集合归纳偏置 |
| 输出对照 | H0、H1；H2 仅非结构零主臂 | 隔离输出几何收益 |

约束：

1. C1 与 M1 同 scaler、head、loss、五 seed、训练预算和参数匹配规则。
2. 不重新搜索 Set Transformer；只有 M1 已通过困难轴门且残差显示稳定交互，才允许另立协议。
3. GF-I07 只有 train-only OOF explained variance 为正、线性修正通过 stress-val 门时才重新开放。
4. 候选选择只使用 val 与 stress-val，不读取 hard test。

晋级门：候选相对主强基线平均改善至少 5%，至少 4 / 5 seed 同向，任一组分绝对退化不超过 0.005；至少两个合格困难轴同向改善，且没有冻结关键轴出现明显失败。

### A2H-7：联合压力、formal test 与关闭评审（3–5 天）

目标：冻结一个候选或负结论，执行一次 hard-test 解锁并形成 A2H 终态。

实施：

1. 在 A2H-6 后冻结候选、baseline、eligible axes、联合压力组合和图表模板。
2. 校验所有 hash 与 `formal_run_status=FROZEN` 后一次解锁全部 hard test。
3. 运行 2000 次 `mixture_id` group bootstrap 和困难轴配对统计。
4. 将算法结果追加到 `08_算法实验结果记录.md`，新建 A2H 评审记录和正式报告。
5. 关闭为 `POSITIVE_RESULT`、`NEGATIVE_RESULT`、`BENCHMARK_SATURATED` 或 `INVALID_DIFFICULTY` 之一，不保留含糊终态。

阶段门：hard test 无调参回流；结论逐困难轴成立；A3 的方法声明和可复用核心已冻结。

## 7. 验证矩阵

| 验证层 | 必做检查 |
| --- | --- |
| 单元测试 | profile 参数化、重复观测分组、上下文可见性、oracle 反演、资格门边界 |
| 数据契约 | 禁止字段、组成闭合、单位、shape、group 互斥、hash 可复现 |
| 协议测试 | hard-test 默认锁、required evidence、配置漂移、A1 hash 不变 |
| 数值回归 | 名义 deterministic signal parity、共享 evaluator 与 A1 metric 语义一致 |
| smoke | 每个 split 族最小规模生成、审计、训练和汇总均可执行 |
| 正式验证 | 五 seed、逐轴分层、2000 次 group bootstrap、最差组与失败案例 |

后端目标测试默认 60 秒超时；正式训练和 bootstrap 另按运行配置登记，不用测试超时掩盖长任务。

## 8. 停止与决策规则

| 触发条件 | 处置 |
| --- | --- |
| A1 deterministic parity 失败 | 停在 A2H-1，修复共享物理或单位问题，不生成正式数据 |
| 困难档位导致 oracle 同时失效 | 标记 `INVALID_DIFFICULTY`，缩回范围并升版协议 |
| concat 与 oracle 在全部档位等价 | 标记 `BENCHMARK_SATURATED`，不扩大算法搜索 |
| 少于两个独立困难轴合格 | A2H 不进入算法比较，记录负结果 |
| H1/H2 只改善物理违规而未过精度稳定门 | 保留输出合法性结果，不作为主候选 |
| M1 不超过 matched C1 | 关闭 Deep Sets，不自动升级注意力模型 |
| residual 只在 in-sample 可预测 | 关闭 residual，不启用二级网络或 ErrorNet |
| 候选只在一个轴或一个 seed 改善 | 不晋级，不用总体平均掩盖 |
| hard test 未通过晋级门 | 冻结负结果，A3 使用强基线或收缩方法声明 |

## 9. 计划交付与完成定义

A2H 的最小完整交付包括：

1. 一个独立、可复现、带多 split 族的 A2H 数据版本；
2. 一个能区分覆盖、噪声、环境和模型失配的难度审计；
3. 学习曲线、噪声响应、环境 OOD、标定失配、组成留出和联合压力结果；
4. oracle、最近邻、B3、B4、B5-like、C1、M1 与输出头 matched 对照；
5. 锁定 hard-test、逐组分和最差轴统计；
6. 追加后的算法实验结果记录、A2H 评审记录和进入 A3 的声明边界。

完成不等于必须产生新算法正结果。只要困难度来源可归因、协议无泄漏、结果可复现且终态明确，A2H 可以以负结果或 benchmark 饱和结论关闭。
