## 1. 核验结论

H0-4 首轮定向核验完成。核验以代码、配置、日志、结果、manifest 和冻结产物之间的可追溯一致性为准，没有启动全量训练，也没有把历史指标拼成跨项目排行榜。

本轮形成四条可执行结论：

- hydrogen_ng 的 gas_head、raw4、softmax100 三组 head 结果存在来源冲突：保存的 `model_config` 使用 `waveform_int16_scale`，当前 PhaseWindowTCN 入口使用 `waveform_adc_scale`；同一 sweep 的 `training.log` 又记录 formal dataset root 不存在。三组 metrics 因此降为 E1，不能支撑 head 排名、N2 性能结论或信息上限结论。
- syngas 的历史 128 步结果与当前 512 步主线已分离。TCN 历史配置改为实际 128 步运行产物；当前 `syngas/configs/sg4_tcn.json` 只代表 512 步新实验，不再作为历史结果的配置证据。
- tunnel_ventilation B7 的冻结证据链闭合到 36 行 protocol matrix：四类协议、三组 split seed、三组 training seed，`protocol_pass=true` 且 `matrix_complete=true`。该结论仍限定在 B7 协议，formal data 为 server-side contract，不能外推为通用端到端模型结论。
- rcdw_mgda 与 GIB 的边界保持负结果或阻塞结果：RCDW 的数据和 checkpoint 未在本地恢复；GIB P3 G3-4 `enter_P4_count=0`，下一步只能回到 P1/P2，不能进入 P4。

## 2. 核验方法

- 先读取任务契约，再将每个结论绑定到具体源码、配置、运行产物或冻结 manifest。
- 检查输出头、scaler、target transform、loss、seed、group split、数据版本、评估 split 和结果入口是否一致。
- 对可改变路线判断的冲突只做高价值定向核验；缺失数据、checkpoint 或 formal data 时保留 `unknown` / `blocked`，不补造重跑结果。
- 代码和产物冲突时，按当前入口能实际接受的契约判断“当前可归因性”，不以文件名或历史文档单独证明一次成功运行。

## 4. 冲突与处置

### 4.1 已确认的契约冲突

hydrogen_ng 的当前代码、迁移文档和 head sweep 配置共同指向 `waveform_adc_scale`；三份保存模型配置却留下 `waveform_int16_scale`。此外，sweep 训练日志在 formal dataset 校验阶段失败。该冲突发生在 artifact provenance / config contract 层，已新增 `FAIL-HG-HEAD-ARTIFACT-DRIFT`，并将三组 head 的 algorithm 与 experiment 条目降级。

### 4.2 尚未判定的结果异常

gas_head 与 softmax100 的 evaluation 对象完全相同，而配置和 checkpoint 不同。当前无法区分真实预测行为、评估器输入复用、旧产物残留或 checkpoint provenance 问题，已新增 `FAIL-HG-HEAD-EQUAL-EVAL` 并保留 `unknown`。在逐样本预测和成功 replay 完成前，不把该相同结果当作参数化等价性证据。

### 4.3 历史配置引用错误

`EXP-SG-STAGE-I3-128` 原先引用当前 512 步配置。本轮已改为 `syngas/outputs/sg4_baseline/tcn/seed42/run_config.json`，并补充历史 runs index 与 128 步运行配置来源。该修订只纠正复盘台账，不修改原始 syngas 产物。

### 4.4 冻结通过与可复现边界

tunnel_ventilation B7 的 protocol pass、freeze audit pass 和 GIB freeze verified 都是有范围的证据结论。B7 的 clean formal data 仍在 server-side contract，GIB 的结论只覆盖冻结候选集；两者均不能被改写成跨任务算法优越性结论。RCDW 则因本地缺失数据和 checkpoint 继续保持 blocked。

## 5. 台账修订结果

- `algorithm_ledger.json`：三组 hydrogen head 保持 E1，并统一使用 `blocked` 状态；具体冲突写入 `conclusion_detail`，继续条件写入 `disposition_condition`。syngas、TV3、RCDW 和 GIB 条目使用同一组结论与处置枚举。
- `experiment_ledger.json`：三组 hydrogen head 保持 `conflicted_unverified_artifact`；补齐 PatchTST、LSTM、TV3 B1、端到端表示、E1/E1d 和 RCDW 机制的独立实验记录，避免借用其他算法的总括实验 ID。
- `failure_ledger.json`：新增 hydrogen head artifact drift 与 equal-evaluation anomaly；每条失败新增 algorithm_id，并与 experiment_id 所指算法保持一致。
- `source_registry.json`：来源细分类型统一映射到 doc、code、config、test、log、output、freeze 和 commit 八类基础来源。

## 6. H0-4 门禁与后续最小判别实验

H0-4 首轮门禁通过：强结论均已绑定最小证据；工程失败、协议失败、算法机制未确认和本地缺失产物已分开；不确定项保留为 `unknown` 或 `blocked`。H0-5 至 H0-8 的首轮工作现已完成，未闭环事项继续保留在下列最小判别路径和 open items 中。

后续只保留以下高价值判别路径：

1. 恢复 hydrogen_ng formal data 后，以 `history_audit` 前缀重放 head sweep，逐项核对入口、model kwargs、scaler、checkpoint 和逐样本预测。
2. 为 syngas 512 建立独立 experiment record；不把 128 步 TCN、Ridge 或 PatchTST 指标迁移为 512 结论。
3. tunnel_ventilation 继续沿 RawDSP / 信息可辨识性 / OOF 结构核验，不恢复已关闭的 generic end-to-end 或 MRS-EI C3 路线。
4. RCDW 先恢复 exact data/checkpoint，再用物理重算扰动和独立 ErrorNet calibration discriminator；在此之前不启用 dynamic weighting 或 hard suppression。
5. GIB 只有在 P1/P2 提出新的信息假设并重新预注册 gate 后才可重开，不从同一失败候选集直接扩展 P4。
