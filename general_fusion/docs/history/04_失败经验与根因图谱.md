# 失败经验与根因图谱

> 核验日期：2026-08-27  
> 阶段：H0-5 首轮完成  
> 适用范围：已登记的 hydrogen_ng、syngas、tunnel_ventilation、rcdw_mgda 与 gas_information_bench 历史证据  
> 唯一失败事实表：[failure_ledger.json](failure_ledger.json)  
> 上游核验：[03_H0-4_证据核验报告.md](03_H0-4_证据核验报告.md)

本页把失败台账中的观察组织成“现象 → 假设 → 区分检查 → 证据 → 根因状态 → 适用范围 → 修复动作 → 残余上限 → 停止条件”。本页负责因果解释和验证闸门；失败 ID、实验 ID、证据来源和原始字段仍以 `failure_ledger.json` 为准，不在此页复制第二份事实表。

## 1. 首轮结论

本轮审查覆盖 13 条失败记录、20 个实验记录、21 个算法记录、6 个任务契约和 63 个来源。13 条失败的必填字段均已存在，且每条都直接绑定算法与实验并具有明确停止条件；没有任何一条被保留为无解释的“模型失败”。

根因状态分为三类：

- 8 条在明确范围内已确认：输出自由度、版本边界、表示损失、协议门失败、扰动语义不一致、候选集闸门失败或产物契约冲突等。
- 3 条有历史证据支持多层解释，但不能压缩成单一根因：通用波形端到端路线、E1 表示族和 Windows LSTM 退出码。
- 2 条必须保持 `unknown`：RCDW ErrorNet 的低相关性来源，以及 hydrogen_ng 两种 head 产生完全相同 evaluation 对象的原因。

因此，本轮得到的最强结论不是“某个大模型不行”，而是：在信息、任务契约、表示保真、输出参数化、可靠性校准和产物溯源尚未闭合时，扩大网络或重新排名都不能增加可信证据。

## 2. 分析边界与判别顺序

### 2.1 证据边界

- 本轮只使用 `source_registry.json`、`task_contract.json`、`algorithm_ledger.json`、`experiment_ledger.json`、`failure_ledger.json` 和其登记的原始来源。
- 没有启动全量历史训练，也没有用当前 512 步配置替代 syngas 历史 128 步配置。
- 缺失数据、checkpoint、server-side formal data 和不一致的保存产物保持 `blocked`、`partial` 或 `unknown`，不补造重跑结果。
- B7 的 protocol pass、MRS-EI 的 hash-verified freeze 和 GIB 的 freeze verified 只在各自协议范围内成立；证据完整不等于科学结论通过。
- 本页的“验证指标”是下一步判别实验必须记录的观测项，不是事后设定的成功阈值。定量收益门应在 general_fusion A0 看到正式测试结果前冻结。

### 2.2 统一判别路径

失败按以下顺序处理，后一个层级不能替代前一个层级的缺失证据：

1. **L0 信息与可辨识性**：输入是否包含区分目标所需的观测量，是否存在 rank 或相关性上限。
2. **L1 数据与协议**：标签、版本、窗口、group、split、scaler 和部署输入是否一致。
3. **L2 表示与预处理**：绝对 TOF、相位、质量量、序列斜率和有效帧是否在编码或 pooling 中保留。
4. **L3 输出与目标**：输出自由度、闭合约束、target scale、低浓度处理和 loss 是否匹配标签。
5. **L4 模型与融合**：只有前四层通过后，才判断分支交互、门控或模型容量是否不足。
6. **L5 鲁棒性与外推**：缺失、退化、冲突、OOD、UQ 和拒识是否使用真实且可解释的协议。
7. **L6 工程与结果完整性**：AMP、退出码、配置加载、checkpoint、metrics 和哈希链是否可信。
8. **L7 主张边界**：结论是否超出任务、数据、split、冻结 gate 或部署条件。

## 7. 对当前主线的阶段性约束

本轮只向 general_fusion 传递结构性约束，不传递跨项目绝对指标：

1. **A0 先冻结契约**：明确输入的真实可观测量、输出自由度、闭合规则、目标尺度、`mixture_id` 分组、scaler 和部署输入；历史 head、旧窗口和旧主键不能直接进入新主线。
2. **A1 先做 cheap baseline 与信息审计**：先比较单模态、Ridge/GBDT、简单拼接和固定融合，并检查多模态是否真的提供互补信息；强基线打平时不启动大模型搜索。
3. **A2 只引入可解释机制**：raw/phase/DSP、输出 head、残差或门控每次只改变一个主要因素，保留对应负对照并记录参数量、效率和分层误差。
4. **A4 先证明质量可观测且可校准**：动态权重、拒识和 hard suppression 都要同时报告 clean cost、真实退化收益、校准和失败率；随机 dropout 不足以代表可靠性。
5. **所有正式运行都通过产物闸门**：入口、配置、数据 manifest、split、seed、checkpoint、metrics、退出码和输出 hash 必须形成一条可追溯链；文件存在不等于运行成功。
6. **主张按范围降级**：protocol pass 只支持 protocol-scoped pass，freeze verified 只支持证据完整；unknown、blocked、superseded 和 formal_fail 不得在摘要中被写成成功。
