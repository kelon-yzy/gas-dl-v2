# 跨项目算法比较矩阵

> 核验日期：2026-08-27  
> 阶段：H0-6 首轮完成  
> 适用范围：H0 首轮已登记的历史任务、算法、实验和失败证据  
> 算法事实表：[algorithm_ledger.json](algorithm_ledger.json)  
> 实验事实表：[experiment_ledger.json](experiment_ledger.json)  
> 根因解释：[04_失败经验与根因图谱.md](04_失败经验与根因图谱.md)

本页只做分层比较和经验合成，不建立跨项目绝对误差排行榜。不同气体对象、浓度范围、窗口、采样率、传感器物理量、标签定义和部署条件不满足同一任务契约时，只比较结构性经验、协议纪律或机制前置条件。

## 1. 比较规则

### 1.1 允许的比较

| 比较类型    | 允许内容                                                                 | 不允许内容                                       |
| ------- | -------------------------------------------------------------------- | ------------------------------------------- |
| 同任务、同版本 | 在相同 task_id、data_version、split、scaler、seed 和 metric definition 下比较算法 | 将不同窗口、不同数据版本或不同标签定义的结果合并                    |
| 同项目历史层  | 比较同一项目内的算法谱系、消融因素和失败边界                                               | 把历史 128 步结果写成当前 512 步结果                     |
| 结构类比    | 比较“固定特征 baseline”“OOF 残差”“质量感知路由”等机制的前置条件                            | 把机制相同写成性能相同                                 |
| 协议类比    | 比较分组切分、冻结、校准、产物 manifest 和失败门                                        | 用另一项目的 gate 数值替代当前项目阈值                      |
| 性能类比    | 仅在完全匹配的任务契约内进行                                                       | 用 hydrogen_ng、syngas、TV3、RCDW 或 GIB 的绝对指标互排 |

### 1.2 证据标签

- `E4` 只表示冻结产物、版本和哈希链达到高完整度，不自动表示算法通过。
- `E3` 可以支持协议内比较，但仍须查看 split、重复、产物和 claim scope。
- `E2` 只支持 smoke 或局部诊断；`E1` 只支持实现或冲突产物存在。
- `formal_pass`、`formal_fail`、`blocked`、`superseded` 和 `unknown` 必须与 evidence_level 分开阅读。

## 2. 按任务契约的比较矩阵

| task_id / 项目                                | 可比较对象                                                             | 当前证据与协议边界                                                                                                                   | 可以合成的经验                                                         | 禁止外推                                                                                       |
| ------------------------------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `TC-HG-V4` / hydrogen_ng                    | `HG-RIDGE-MW` 与 PhaseWindowTCN 的 gas_head、raw4、softmax100         | Ridge 为 E2；三组 head 为 E1，且保存配置、当前入口和训练日志冲突                                                                                   | 先固定输入 scaler、输出自由度和闭合规则，再解释 N2；多窗口固定特征可作为 cheap baseline 角色     | 不把 head metrics 排名；不把 gas_head 的 N2 结果写成传感器信息上限；不跨任务搬运四组分闭合                                |
| `TC-SG-SG4` / syngas                        | `SG-RIDGE-128`、`SG-TCN-128`、PatchTST fp32/fp16、LSTM、loss ablation | 现有结果属于 `sg4-formal-128` 历史层；当前配置是 512；fp16 是工程变体，逐 run artifact audit 尚未完成                                                  | 结果必须绑定时间窗口；工程数值设置和科学模型结论分开；Ridge 是必要参照                          | 不把 128 指标当 512 结论；不因 fp16 NaN 关闭 PatchTST 架构；不因 Windows 退出码单独判科学失败                         |
| `TC-TV3-TUNNEL` / tunnel_ventilation        | B1 RawDSP、B7 OOF residual、E1/E1r/E1d-SB、端到端 waveform、MRS-EI       | B7 在自身 36 行 protocol matrix 上 pass；clean formal data 为 server-side contract；MRS-EI C2 freeze verified 但 semantic not_passed | 观察量、校准质量、序列信息和 OOF 纪律比网络名称更有迁移价值；baseline-plus-residual 是受限结构模式 | 不把 B7 的 protocol pass 写成通用端到端优越；不把 MRS-EI freeze 写成 UQ 通过；不从 frame metric 晋级 frame-only 表示 |
| `TC-RCDW-1` / rcdw_mgda                     | MGDA、ErrorNet 动态权重、hard suppression、扰动诊断                          | E2；本地 data、runs、checkpoint 缺失；扰动记录为 standardized-space；ErrorNet 根因 unknown                                                  | 可靠性路由必须先有真实质量观测、独立校准和 clean-cost gate；扰动单位和生成链必须明确              | 不把文档数值当 E3/E4；不把随机或标准化扰动写成物理退化；不启用未校准的动态权重                                                 |
| `TC-GIB-CONTROLLED` / gas_information_bench | P2 Ridge baseline 与 P3 七类候选集合                                     | P2 baseline 用于 baseline role；P3 G3-4 为 E4 freeze-backed candidate-set fail，`enter_P4_count=0`                               | 信息假设和预注册 gate 应先于候选扩展；候选集关闭是有价值的负对照                             | 不把 P3 候选集失败写成 general_fusion 全局不可行；不从同一前提直接进入 P4                                           |
| `TC-XYLENE-EXTERNAL` / xylene_external      | 目前只有数据契约和任务边界，无历史算法结果闭环                                           | 六路 QCM 是同一物理原理阵列；按完整 workbook 分组；标签和近饱和边界已知                                                                                 | 外部验证首先检验适配器、文件级 split、标签边界和共享核心接口                               | 不把六路 QCM 写成六种异构模态；不声称 zero-shot；不从气体模拟绝对误差外推 ppm 结果                                        |

## 3. 机制—观测量—证据对照

| 机制类别                       | 历史代表                                         | 所需真实观测量或协议                                                        | 已知证据                                                           | 可继承结论                                           |
| -------------------------- | -------------------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------- | ----------------------------------------------- |
| 固定特征强 baseline             | HG Ridge、SG Ridge、TV3 B1、GIB P2              | 明确的统计量/DSP、训练组拟合的 scaler、group split                              | HG 为 E2；SG、TV3、GIB 各有任务内历史入口，证据等级和 scope 不同                    | baseline 是确定信息上限、互补性和误差结构的必要参照；不继承绝对指标          |
| 多窗口或 phase-window 表示       | HG PhaseWindowTCN 家族                         | 窗口边界、采样率、波形 scale、相位/绝对 timing 语义                                 | head sweep 产物存在 config conflict；当前不能闭合 head 比较                 | 先做输入复原和 output-head matched audit；不把结构名称当作机制证据  |
| 原始波形端到端                    | TV3 generic waveform、E1/E1r                  | 绝对 TOF、序列斜率、calibration、PSR、SNR 和 pooling 后的有效信息                  | TV3 历史失败为多层支持，不能压缩为容量不足                                        | raw input 只有在关键观测量保留且可部署时才有意义                   |
| OOF baseline-plus-residual | TV3 B7                                       | 训练外基线预测、OOF residual、明确协议矩阵和分层 OOD                                | E3、36 行 protocol matrix、protocol pass；clean formal data 仍有部署边界 | OOF 纪律和残差结构可以作为 A2 的结构性候选；必须在新 task contract 重写 |
| 输出闭合与参数化                   | HG gas_head、raw4、softmax100                  | 独立输出自由度、闭合规则、target transform、component-wise metrics              | gas_head N2 结论只在自身语义内成立；三组 head artifact conflict              | 输出头是独立实验因素；先冻结标签语义，再比较网络                        |
| 动态权重与 hard suppression     | RCDW ErrorNet、hard suppress                  | 可观测质量、独立误差标签、clean/degraded/冲突集和校准协议                              | E2 诊断；ErrorNet correlation unknown，hard suppress 有 clean cost  | 动态路由只能作为受控机制实验，不能默认优于静态融合                       |
| UQ、拒识和冻结 gate              | TV3 MRS-EI、GIB P3                            | calibration、coverage、interval width、OOD/拒识、预注册 gate 和 freeze hash | MRS-EI semantic not_passed；GIB candidate-set E4 fail           | 证据完整度、科学 gate 和部署有效性必须分字段记录                     |
| 工程运行完整性                    | syngas AMP/exit、HG artifact drift/equal eval | run config、入口、data root、checkpoint、metrics、退出码、输出 hash            | 多个历史冲突和工程假失败已登记                                                | 工程 manifest 是科学证据的前置条件，不是事后补充                   |

## 4. 历史方法处置矩阵

| 处置                 | 算法或路线                                                                                                                     | 进入 general_fusion 的内容                  | `disposition_condition` 所表达的前置条件与负对照                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- | ---------------------------------------------------------------------- |
| `inherit`          | `TV3-B1-RAW-DSP-RIDGE`、`TV3-B7-OOF-RESIDUAL`、`HG-RIDGE-MW`、`GIB-P2-RIDGE-BASELINE`                                        | baseline 角色、OOF residual、分层协议和信息审计纪律 | 新 task contract 重写；训练组 scaler、group split、指标和重复闭合；不迁移绝对误差          |
| `rewrite`          | syngas 的 TCN、Ridge、PatchTST fp32、LSTM、inverse-train-var loss                                                              | 窗口、目标尺度和损失的研究问题                        | 单独 512 manifest 和结果；128 历史层作为 superseded 对照；fp16 只作工程负对照          |
| `park`             | hydrogen_ng raw4/softmax100、RCDW Phase6E 与 ErrorNet                                                                      | 输出 head 审计、质量预测和动态路由的待验证问题             | 恢复 exact 资产；完成逐样本 provenance、独立校准、真实物理扰动和 clean-cost gate       |
| `negative_control` | HG gas_head 冲突产物、syngas fp16、TV3 E1 frame-only、RCDW hard suppression、GIB P3 candidate set                              | 用于证明常见误区不会自动带来可信收益                     | 保留失败、gate 和 scope；不能删除失败 seed 或放宽判定                                    |
| `close`            | TV3 generic end-to-end、MRS-EI C2                                                                                          | 只保留关闭理由和必要负对照                          | 如要重开必须是新协议、新信息假设或新 gate；不能静默延续旧路线                                      |

`unknown` 是结论状态，不在处置字段中承载。HG equal-evaluation anomaly 与 RCDW ErrorNet 根因继续使用 `conclusion_status=unknown` 或 failure root-cause `unknown`，对应路线处置为 `park`。

## 5. 面向新主线的研究假设

这些是假设卡的输入，不是 H0 阶段已验证的模型结论。

| 假设 ID    | 研究问题                                              | 最小验证                                                                    | 若不成立的处置                         |
| -------- | ------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------- |
| H-SYN-01 | 当前多传感输入是否比最佳单模态包含可辨识的互补信息？                        | A0/A1 做单模态、Ridge、简单拼接和固定融合；按 `mixture_id` 分组并报告误差结构                     | 回到数据或物理设计，不启动大型融合搜索             |
| H-SYN-02 | 输出参数化和 target scale 是否比更深 encoder 更先决定低浓度和闭合组分表现？ | 固定 encoder 做 raw/闭合/任务头/scale 单项消融；记录分组与 component-wise metrics         | 固定输出契约，关闭无法归因的结构扩展              |
| H-SYN-03 | 保留绝对 timing、质量量和序列斜率是否改善部署可用表示？                   | 输入复原、pooling parity、质量特征消融、OOD/分层误差                                     | 若观测量不可得，关闭依赖它的路线，不用扩容替代         |
| H-SYN-04 | OOF baseline-plus-residual 是否能在新任务中提供可归因增益？       | OOF baseline、residual、无 residual 和随机残差对照；冻结 split 和训练 seed              | 保留 baseline，关闭残差机制              |
| H-SYN-05 | 从当前输入能否稳定估计可用于路由的质量或误差？                           | 独立 ErrorNet calibration、component-wise reliability、真实退化、clean cost 和拒识率 | 动态权重停留在 park 或 negative control |
| H-SYN-06 | 同一融合核心能否通过适配器复用到 xylene？                          | 完整 workbook split、标签审计、同核心独立训练和强基线                                      | 收缩为架构适配范围分析，不宣称 zero-shot       |

## 6. H0-6 阶段门审查

| 阶段门               | 结果  | 依据                                            |
| ----------------- | --- | --------------------------------------------- |
| 比较矩阵每个单元有可解释依据    | 通过  | 第 2、3 节绑定 task_id、data_version、证据等级、协议边界或结构类比 |
| 没有用不同任务绝对指标进行虚假排序 | 通过  | 本页不复制绝对指标，只保留同任务范围和机制条件                       |
| 每条继承建议带前置条件和负对照   | 通过  | 第 4、5 节逐项给出前置条件、最小验证和失败处置                     |

H0-6 首轮结论：可向 general_fusion 传递的是 baseline、信息审计、OOF 纪律、输出契约、真实质量校准和产物完整性等结构性经验；不能直接传递历史权重、固定通道实现、旧窗口、旧主键、绝对性能或未校准动态权重。

下一阶段 H0-7 应把第 5 节假设映射到 general_fusion A0-A6 的研究卡和阶段门，不在 H0 阶段选定最终模型。
