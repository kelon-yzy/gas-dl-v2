# H0-8 反向审稿与冻结前检查

> 审查日期：2026-08-27  
> 阶段：首轮反向审稿与台账质量修订完成  
> 审查范围：H0 首轮历史证据层和 general_fusion A0-A6 映射  
> 当前主线事实源：[general_fusion/项目总体规划.md](../../项目总体规划.md)  
> 历史复盘入口：[README.md](README.md)

本页是 H0 首轮 adversarial review，不是新的算法结果。审查目标是尝试用已有来源推翻高价值结论、检查来源链和状态语义，并列出必须显式保留的 open items。

## 1. 审查对象与快照

当前登记包含 6 个任务契约、21 个算法、20 个实验、13 个失败记录和 63 个来源。历史目录已形成 00–08 说明页及五类 JSON 登记文件；[history_freeze_manifest.json](history_freeze_manifest.json) 保留首轮质量修订前的证据快照，当前台账完整性由自动测试独立检查。

审查遵循以下边界：

- 只使用登记来源、代码、配置、日志、结果 bundle、freeze manifest 和 review record；不以未登记口头结论补齐证据。
- `E4` 表示证据完整度，不自动表示算法或 gate 通过；`formal_pass`、`formal_fail`、`blocked`、`superseded` 和 `unknown` 分开记录。
- syngas 128 步、当前 512 步、历史 smoke、server-side formal data 和缺失 RCDW 产物不合并。
- 任何历史绝对指标都不跨任务契约排序；general_fusion 只接收结构性约束和带前置条件的研究卡。

## 2. 反向审稿结果

| 待审查主张 | 试图推翻的方法 | 审查结果 | 保留的准确表述 |
| --- | --- | --- | --- |
| gas_head 说明 N2 不可学 | 比较 matched raw4/softmax100，检查是否只是输出自由度造成 | 广义主张被推翻；匹配 head 尚未因产物冲突闭合 | 仅能说在记录的 gas_head 语义内 N2 没有独立输出自由度 |
| syngas 128 结果可代表当前 512 | 检查 config、manifest、window、split 和 result_ref | 被推翻 | 128 是 superseded historical；512 必须独立建账和重评 |
| PatchTST 架构本身失败 | 用同结构 fp32 对照区分数值执行和架构行为 | 被推翻 | 当前只确认 fp16 execution variant 的工程失败 |
| Windows LSTM 非零退出意味着模型失败 | 分离 exit code、checkpoint、final step 和 metrics 完整性 | 被推翻 | 退出码是工程信号；受影响 seed 的科学状态需 artifact audit |
| TV3 B7 pass 证明通用端到端模型有效 | 检查 B7 的 36 行协议、输入特征、OOD 和 clean formal data 边界 | 被推翻 | B7 只支持自身 protocol-scoped pass 和 OOF residual 结构经验 |
| frame-level E1 恢复足以支持序列预测 | 检查 absolute timing、sequence slope、calibration、PSR 和 SNR | 被推翻 | frame metric 不能替代 sequence-level 表示和部署质量量 |
| MRS-EI freeze 完成等于科学通过 | 分离 hash/evidence completeness 与 semantic verdict、C3 authorization | 被推翻 | C2 evidence freeze verified，但 semantic verdict not_passed |
| RCDW ErrorNet 可直接用于动态权重 | 检查独立校准、组件误差相关性、真实扰动和 clean cost | 未能推翻风险，主张不成立 | ErrorNet 机制仍 unknown/park；hard suppression 只作负对照 |
| GIB P3 候选失败证明全局问题不可行 | 将结论限制到候选、cells、split、seed 和 G3-4 gate | 被推翻 | 只有冻结候选集在预注册 gate 下未晋级 |
| general_fusion 代码所有权路径已一致 | 对照计划、README、pyproject、测试和实际目录 | 首轮发现漂移后已修正 | 当前项目计划与骨架统一为 `src/gf/*`，A0 仍需自动检查 |

反向审稿没有发现可以把上述限定结论升级为更强结论的证据；相反，所有冲突都已收缩到 scope、evidence、status 或 open item。

## 4. 必须随冻结快照保留的 open items

这些事项不阻止把本轮“证据层快照”冻结，但阻止把相关历史路线写成已复现或正式通过：

1. `SRC-TV3-CLEAN-FORMAL-MISSING`：代码契约声明的 clean formal data 不在本地，旧污染目录不能替代。
2. `SRC-RCDW-DATA-MISSING`：RCDW data、runs 和 checkpoint 未恢复，不能升级诊断数值的 evidence level。
3. hydrogen_ng 三组 head 的保存 metrics 与训练日志、scaler 和 formal data root 冲突；需要 `history_audit` replay 才能比较。
4. hydrogen_ng gas_head 与 softmax100 的 equal evaluation anomaly 仍是 `unknown`，需逐样本 prediction 和 evaluator provenance。
5. syngas 历史逐 run artifact audit、LSTM 退出码影响范围和 Stage II exact cell mapping 仍未完成。
6. syngas 当前 512 步 formal result 尚未闭环；历史 128 步只保留为 superseded 对照。
7. 计划范围内尚未登记的算法族已列入 [02_历史算法谱系.md](02_历史算法谱系.md) backlog；在逐条建立来源、契约和实验身份前，不得计入 H0-3 完成范围。

## 5. 首轮审稿判定

本轮审查结论为：**当前登记集合已经通过结构、引用和语义一致性检查，但不能把它描述为所有历史实验已复现或所有计划内算法已登记。**

后续 H0 收敛必须持续满足：

- 缺失、冲突、blocked、unknown、superseded 和 not_passed 状态不被清理或改写；
- 受控枚举、跨表引用、算法—实验—失败一致性和 Markdown 链接自动检查通过；
- general_fusion 只依据本快照进入 A0 契约工作，不直接恢复旧模型或开启长时间搜索。

H0-8 首轮评审与质量修订标记完成；未解决 open items 转入后续定向复查和 A0/A1 的正式门禁。H0 整体仍保持 `IN_PROGRESS`，因为 H0-1/H0-2 的穷尽扫描、计划内算法补登、历史重放和缺失资产恢复尚未完成。
