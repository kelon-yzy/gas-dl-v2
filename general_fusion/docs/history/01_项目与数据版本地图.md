## 2. 版本边界

### 2.1 hydrogen_ng

- v4 schema 将 mixture_id 作为 primary key，sequence_id 作为 instance key；四个 split 仍按 mixture_id 分组。
- wv4-smoke manifest 是可直接核验的 v4-benchmark-1 资产，包含 128 个时间步和慢、超声、光纤三类输入形状。
- hitran-usable-20260527-seed42 是本地另一个可用输出入口，时间步数和波形长度与 wv4-smoke 不同，必须单独登记。
- N2 诊断文档和 n2_head_sweep 配置指向 wv4-formal-hitran-standard-6000；当前本地数据目录没有与该名称完成闭环的 formal manifest，因此不能把它与 smoke 或 hitran-usable 合并。
- 旧整理文档中的 waveform_v3、120 步、int16 乘 per-timestep scale 等定义保留为 legacy 版本，不能覆盖 v4 schema 或 smoke manifest。

### 2.2 syngas

- Stage I、Stage II 的已报告结果属于 sg4-formal、128 步历史层，仍可用于历史对照和失败复盘。
- 2026-06-27 后当前配置使用 target_timesteps=512；本地 syngas/data 只有 sg4-smoke，未发现对应的 formal 512 结果闭环。
- 因此 128 步结果的 status 是 superseded/deprecated，而不是 invalidated；它们可以说明当时协议内的行为，不能证明 512 步主线表现。
- PatchTST 的 fp16 NaN、LSTM 的 Windows 退出码和 loss weighting 结论分别登记，避免把工程故障与模型结论混在一起。

### 2.3 tunnel_ventilation

- 掘进通风契约将 CO2、O2、N2 全部作为显式目标；不允许沿用氢气项目的 N2 closure、gas_head、ILR 或 ALR 语义。
- tv3-formal-6000 clean 资产在契约中是服务器侧 formal 数据；本地 tv3-formal 旧目录含 V_NDIR_CH4，属于污染的 debug 资产，不能作为 clean formal 证据。
- outputs/runs 与冻结目录可以支撑算法、协议和 verdict 的历史登记，但本地存在不等于当前可重新训练。
- MRS-EI 的 freeze 有完整 manifest/hash 和 closed verdict，但 semantic verdict 是 not_passed；“已冻结”不等于“算法通过”。

### 2.4 rcdw_mgda 与 gas_information_bench

- RCDW 代码和 Phase6E 配置定义了独立 schema、ID 和窗口；诊断文档所述 checkpoint/data 当前本地缺失，结论证据等级不能按完整 formal 处理。
- GIB 的 P2/P3 freeze 是当前最完整的冻结证据之一；P3 G3-4 的结论是候选集合未通过闸门，而不是整个 general_fusion 任务不可行。
