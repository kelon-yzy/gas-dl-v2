## 1. 复盘目标

本轮产物是可追溯的历史知识库，不是跨项目的总模型排名。每个历史结论都必须能够回到来源、版本、数据、协议和结果证据；无法回溯的内容保留为 unknown，不用经验判断补齐。

当前复盘范围包括：

- hydrogen_ng：四组分 H2、CH4、CO2、N2，慢通道、多窗口统计、超声和光纤波形，以及 Ridge、SVR、PLS、XGBoost、CNN1D、TCN、LSTM、GRU、Transformer、CNN-LSTM、BranchFusion、PhaseWindowTCN 和不同输出头。
- syngas：H2、CH4、CO2、CO 目标，N2 背景，TCN、Ridge、PatchTST、LSTM、CNN1D，以及 CO 通道、串扰和损失加权实验。
- tunnel_ventilation：CO2、O2、N2 任务，D0、D2、R5、D2b、B7、Module C、EC-MSW、双向表示、MRS、MRS-EI、Rocket、MiniRocket、ExtraTrees、UQ 和 solver 路线。
- rcdw_mgda：单模态、ErrorNet、动态权重、hard suppression、alpha/maxShift 和扰动实验。
- gas_information_bench 及 docs/p1、docs/p2、docs/p3：信息上限、Jacobian/Fisher、候选算法闸门和 P3 失败证据。
- 数据集/xylene：作为 general_fusion 的外部验证任务上下文登记，不与上述气体模拟任务合并。

## 2. 首轮冻结规则

### 2.1 来源优先级

发生冲突时，按以下顺序核验：

1. 带 manifest、冻结目录、哈希和 verdict 的冻结产物。
2. 可执行 schema、数据生成器、训练入口、配置和测试。
3. 完整 result、metrics、日志和可复现实验产物。
4. 实验计划、复盘文档、研究笔记和口头性结论。

低优先级来源不能覆盖高优先级事实。若高优先级来源本身不完整，登记为冲突或 unknown，并保留两端路径。

### 2.2 结论类型

每条内容必须标记为以下之一：

- fact：来源直接给出的事实，例如字段、版本、路径、指标或退出状态。
- explanation：已有证据支持的机制解释，必须写明证据范围。
- hypothesis：尚未被区分实验确认的假设。
- recommendation：面向下一步的建议，不回写成历史事实。

算法台账只保存可追溯的 fact 和带范围的 explanation；hypothesis 与 recommendation 放在对应字段中，不得伪装成根因。

### 2.3 证据等级

| 等级  | 定义                            |
| --- | ----------------------------- |
| E0  | 只有想法、规划或未经验证的推断               |
| E1  | 有代码、配置或接口，但没有可信运行结果           |
| E2  | 有 smoke、单次或本地运行结果，协议或复现链不完整   |
| E3  | 有正式协议、完整结果、明确 split，并有必要的重复验证 |
| E4  | 数据、配置、代码、环境、结果和哈希冻结，能够独立复现    |

confidence 只表示证据完整度，不表示算法质量。历史的 formal_pass 或 formal_fail 必须同时绑定适用范围，不能外推到另一个数据版本或任务。

### 2.4 项目隔离不变量

- hydrogen_ng 的主键语义保留 mixture_id；sequence_id 只作为实例标识，禁止回写为主键。
- 新正式 benchmark 不依赖 base_condition_id、noise_seed_index、noise_seed。
- rcdw_mgda 使用 rcdw-benchmark-1 和 RCDW-M/Q 命名空间，与 wv4-*、sg4-* 隔离。
- syngas 的 128 步历史结果与当前 512 步配置分开登记，不互相覆盖。
- 各项目的 split、scaler、输出头、指标和部署假设分开登记。
- oracle 输入只可用于审计或辅助诊断，不能被写成部署输入。
- 不以扩大网络规模掩盖信息不可辨识、表示损失、单位错误或协议失配。

## 3. 台账职责

| 台账                     | 唯一职责                                 |
| ---------------------- | ------------------------------------ |
| source_registry.json   | 来源、版本、日期、路径、状态和冲突备注                  |
| task_contract.json     | 输入、输出、采样、窗口、传感器、标签、分组、split、预处理和可辨识性 |
| algorithm_ledger.json  | 算法谱系、输入表示、融合形式、输出头、机制主张、证据和处置        |
| experiment_ledger.json | 实验配置、数据版本、split、seed、指标、结果、退出状态和复现链  |
| failure_ledger.json    | 症状、层级、假设、区分证据、根因状态、残差上限和修正动作         |

JSON 台账是字段事实的唯一登记处；本目录 Markdown 页面不另建第二套同名事实字段。

## 4. 本轮边界

本轮已完成的是首轮关键来源收敛、关键任务契约建立和首批算法/失败条目登记。尚未完成的内容包括：

- 全量历史文件的逐项来源登记、版本哈希和时间线；
- 所有算法的逐条输入/输出/损失/部署复核；
- 结果文件与配置、数据 manifest 的一一闭环；
- 失败机制的定向 discriminator 实验；
- 缺失历史资产恢复，以及基于恢复资产的定向重放。

首轮 H0-5 至 H0-8 的失败分析、跨项目比较、A0-A6 映射和反向审稿已经完成。当前缺口属于覆盖范围与复现闭环，不再把已完成的首轮映射写成未开始。

因此，当前台账中的 initial_critical、partial、unknown 和 missing 是有意保留的状态，不是默认值，也不是成功标记。

## 5. 验收闸门

当前已登记集合必须持续满足：

1. 每条算法记录有 source_refs 和 task_id。
2. 每条正式指标记录有 result_ref、data_version、split_and_group 和 metric_definition。
3. 128/512、smoke/formal、oracle/deployment、历史/当前等边界没有合并。
4. 每条失败记录区分 fact、explanation、hypothesis 和 recommendation。
5. 任何跨项目迁移只迁移结构性经验，不迁移绝对指标。
6. `conclusion_status` 和 `disposition` 只使用冻结枚举，范围与继续条件分别写入 `conclusion_detail` 和 `disposition_condition`。
7. 每条失败直接绑定 algorithm_id，且与 experiment_id 所指实验的 algorithm_id 一致。
