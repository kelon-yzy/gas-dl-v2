# DataLoader Worker Sweep Recovery Proposal

## 来源摘要
B 组 DataLoader worker sweep 已完成单 run 实测：B0（`num_workers=0`）首个 epoch 为 21.1 samples/s，B2（`num_workers=4`）为 91.98 s/epoch、49.0 samples/s，B3（`num_workers=8`）为 99.40 s/epoch、45.2 samples/s。需要把这组结果记录到 `daily_logs/`，并同步到 `rolling_summary.md`，然后据此进入 B4 常驻 worker 验证。

## 来源类型与可信级别
来源类型：本地实验输出与配置文件。可信级别：B0/B2/B3 的实测值可信度高；B4 作为后续动作依据，可信度中等。

## 候选当前状态事实
- B1 基线仍为 96.37 s/epoch、49.16 samples/s。
- B0 明显慢于 B1，不应作为正式训练口径。
- B2 与 B1 基本持平。
- B3 明显回退，说明 worker 过饱和。

## 候选里程碑事件
- 完成 `phase_window_tcn_ablation` 的 B0/B2/B3 worker sweep 单 run。
- 确认 B2/B3 配置可解析并通过校验。
- 确认 worker 数 8 对该工作负载过高。

## 候选判断反转
- `num_workers=8` 不是下一个稳妥点。
- `num_workers=2` 仍是正式基线。
- B4 应改为 `num_workers=2` + `persistent_workers=true`。

## 候选下一步变化
- 将 B 组结果追加到 `daily_logs/`。
- 将当前结论同步到 `rolling_summary.md`。
- 创建 B4 配置并运行单 run 验证。
- 保持 Phase 1 正式基线不变，直到 B4 证明有收益。

## 与当前 sidecar 的冲突
当前 sidecar 里尚未包含 B 组 sweep 结果和 B4 配置；除此之外，现有正式基线与实验方向一致。

## 建议提升动作
批准把 B 组测量结果提升到 `daily_logs/` 和 `rolling_summary.md`，并批准据此生成 B4 常驻 worker 验证。提升目标：`rolling_summary.md` 和 `daily_logs/`。

## 审阅结论
建议接受。B 组 sweep 是可持续的项目更新，应该记录为当前连续性。
