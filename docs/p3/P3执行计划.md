P3 只回答：在同一冻结合成条件、同一数据与同一预算下，预注册候选是否相对强基线表现出可重复的精度、求解、采样、数据或部署效率优势。

## 2. Task · P3 总目标与完成定义

P3 的目标是按成本从低到高完成以下证据链：

1. 证明冻结前向与所有负对照成立；
2. 证明 9 个信息 × 夹角单元真实可达；
3. 生成并冻结 pilot，证明数据完整、无 split 泄漏、无 oracle 泄漏；
4. 运行强基线和 oracle，确认 critical 单元中仍有可争夺空间；
5. 逐行完成 active 候选和被触发的 conditional 候选最小证伪；
6. 至少一个算法机制取得 `进入 P4`，否则按预注册规则结束 P3 并返回 P1/P2；
7. 只有 G3-4 通过后，才生成、打包、校验并冻结正式数据集。

P3 完成必须同时满足：

- `G3-1=pass`、`G3-2=pass`、`G3-3=pass`、`G3-4=pass`、`G3-5=pass`；

- 至少一个 `candidate_verdict=enter_P4`；
- 所有作为结论依据的证据均来自可通过 `gib verify-freeze` 的 freeze；

### 3.3 唯一状态与 verdict 字段

| 层级 | 字段 | 允许值 | 规则 |
|---|---|---|---|
| 任务 | `task_status` | `not_started` / `in_progress` / `completed` / `failed` / `blocked` | `completed` 要求任务产物已冻结并通过独立校验；执行结束但尚未 freeze 仍为 `in_progress` |

### 3.4 冻结门值缩写

| 缩写 | 当前定义 |
|---|---|
| `NI` | 候选减配对对照的分组分 P90 差之 95% CI 上界，对 `N2/CO2/O2/Ar` 分别不超过 `0.008/0.003/0.010/0.005 mol/mol`，四组分必须同时通过 |
| `E30` | iterations 或 forward calls 相对下降的 95% CI 下界达到 30% |
| `E20` | solver wall-clock 或 batch-size-1 latency 相对下降的 95% CI 下界达到 20% |

## 4. 全局不变量

1. 不得在看到 pilot、baseline 或候选结果后修改 P2 门值、单元、split、seed、bootstrap、预算或硬件 profile。
2. 不得将 `mixture_id` 回退或重写为 `sequence_id`；不得引入 `base_condition_id`、`noise_seed_index`、`noise_seed`。
3. 可复现随机状态写入 attempt/config 元数据，不写成上述历史样本字段。
4. 同一 `mixture_id` 在同一 split 中只能属于一个 partition；所有方法使用完全相同的测试组。
5. hyperparameter tuning 只允许使用 train group；validation 只作预注册选择；test 在配置与模型冻结后一次性读取。
6. oracle 字段不得进入 deployment loader、DSP 特征、候选输入、超参数选择或停止策略。
7. Raw 与 DSP 必须由同一 Raw manifest 配对；DSP 产物必须记录 Raw manifest、DSP config 和 code hash。
8. CPU 与 GPU 结果分轨报告，不合并；不同硬件、线程或软件指纹的配对无效。
9. 计时固定 30 次独立重复、每次 10 个 warmup batch 和 30 个 timed batch，batch size 为 `1/32/256`；只对形成正式成本结论的候选与配对参考执行完整重复，并在同一单元内随机交错运行。未进入成本结论的模型不得仅为保持矩阵对称而重复训练。
10. 非收敛、超时、数值错误和计时异常保留为失败行，不删行、不补值、不切换 solver 或模型。
11. XGBoost、MLP、TCN 或候选依赖不可用时明确失败；不得用另一个模型静默代替。
12. attempt 可以失败，freeze 只能来自 `status=complete` 的 attempt；修复后创建新 attempt，不覆盖旧目录。
13. G3-1/G3-2 未通过前不生成 pilot；G3-3 未通过前不运行候选；G3-4 未通过前不生成正式数据。
14. 所有 active 行都必须达到终态，不能在第一个候选通过后停止其余 active 行；conditional 行只能由表内激活门触发。
15. 没有候选晋级是合法阶段结论，必须返回 P1/P2，不得直接进入 P4。

3. 生成 5 个 group split 与嵌套训练子集，验证 group 无交叉。
4. 验证 Raw → DSP provenance、数组 shape/dtype、单位、有限值、组分范围和总量约束。
5. 验证 oracle 表与 deployment 表字段不相交；deployment loader 做反向泄漏负对照。
6. 验证所有单元、split、partition、模态和组分计数符合 pilot plan。
7. 记录失败行与生成异常；任何缺失不得补默认值或删样本后继续。
8. 完整 attempt 标记 `status=complete` 后使用 `gib freeze` 冻结 pilot，并立即 `verify-freeze`。

**通过：** `pilot_integrity=pass` 且 freeze 可独立重算全部 hash。

**失败：** `gate_verdict=fail`，修正生成链并创建新 attempt；不运行强基线。

### P3-05 · 强基线、oracle 与 G3-3 充分性门

**输入：** 冻结 pilot、S4 registry、三个 critical 单元 `GIB-S1-CRI-HIG/MED/LOW`。

**允许修改：** baseline/oracle runner、训练配置、指标与报告实现、目标测试、G3-3 attempt/freeze。禁止修改 pilot、split 或 P2 门值。

**动作：**

1. 在首次 fit 前冻结 Ridge、GBDT、`xgboost_strong_table`、`mlp_fixed`、`tcn_fixed` 的精确依赖、特征、超参数或 train-only 搜索空间。
2. 所有调参与模型选择只访问 train/validation group；测试 loader 在配置和模型 hash 冻结后开启。
3. 分别运行 CRB、oracle、measurement DSP 和 strong baseline 四层；结果写入隔离表。
4. 对每个 grid/split/seed/component 报告 P90、RMSE、MAE、R²；不得只报宏平均。
5. 在三个 critical 单元逐格计算 oracle 与最强 deployment baseline 的差。
6. 运行 oracle 泄漏、标签打乱、split 交换和重复 ID 负对照。
7. 输出完整性 verdict、baseline gap、模型/输入/代码 hash 与冻结报告。

**G3-3 通过条件：** 数据完整性全部通过，且三个 critical 单元中至少 2 格满足：

```text
oracle_r2 - strongest_deployment_baseline_r2 >= 0.05
```

或者至少一个组分满足：

```text
strongest_baseline_p90 - oracle_p90 > 该组分 NI 带
```

其中 NI 带固定为 `N2/CO2/O2/Ar = 0.008/0.003/0.010/0.005 mol/mol`。

**失败：**

- 完整性失败：返回 P3-03/P3-04 修生成链；
- 强基线打平 oracle：记录 `no_algorithmic_headroom`，返回 P2-04 至 P2-07 重设 bench；
- 任一种失败均不得进入 G3-4。

### P3-06 · C2-S0 普通变量投影 solver preflight

**输入：** G3-3 freeze、Joint LM、Classical VP、VPLR、TSVD/Ridge-VP 固定实现。

**允许修改：** `gib.audit.solver`、solver 配置、difficulty 记录、配对统计与报告。禁止建立展开网络。

**动作：**

1. 冻结相同初始化、预算、终止条件、容差和 forward-call 定义。
2. 在 9 格 × 5 split × 3 seed 上配对运行全部 solver。
3. 记录 P90、iterations、forward calls、wall-clock、非收敛率、condition number 与 final residual。
4. 执行信息档标签打乱和“关闭投影的同实现 Joint LM”负对照。
5. 以 paired group bootstrap 计算 NI、E30/E20、NR5；逐单元与 seed 报告。
6. 检查优势是否由单一单元、单一 seed 或删除失败运行驱动。

**通过：** 至少一个 VP 系方法相对 Joint LM 满足 `NI AND (E30 OR E20) AND NR5`，且不是单格/单 seed 驱动。

**输出：** 该任务只给 `c2_preflight=pass/fail`，不签发 `enter_P4`。pass 仅激活 P3-10；若至少两个 solver 在不同区域分别清除 E30/E20，同时激活 P3-12。

### P3-07 · C5-A CRB 自适应采样

**输入：** 冻结 pilot 的 Fisher/CRB、增量信息与成本字段，G3-3 强基线。

**允许修改：** 自适应停止策略、运行配置、指标与报告；禁止先建网络寻找效果。

**阶段 A · 廉价前置：**

1. 比较完整采样、固定短窗口、uncertainty early exit、CRB early exit、CRB + 动态模态。
2. 在 9 格中模拟停止，必须覆盖 critical 与 insufficient 档。
3. 报告 NI 下的测量时间、采样点、激活模态数，以及 `Delta I`、`Delta I / Delta cost` 和 FLOPs。
4. 执行随机停止、等长度固定窗口和 CRB 排序打乱负对照。

只有 `NI` 且至少一项原生成本下降 20%、其余 primary cost 满足 NR5，才进入阶段 B。

**阶段 B · 最小实现：** 用同一冻结停止策略真正截断输入并重跑预测/求解，不允许再调阈值；重复 9 格 × 5 split × 3 seed 配对评估。

**终态：** 阶段 B 仍清除同一门时 `candidate_verdict=enter_P4`；否则 `reject`。阶段 A 失败时立即 `reject`，不实现完整模型。

### P3-08 · C5-B FO-MPLSELM 与数据效率

**输入：** 冻结 DSP、嵌套训练 group、S4 数据效率与计时协议。

**允许修改：** PLS、ELM、PLSELM、FO-MPLSELM、轻量 CNN 的固定实现和配置；复用既有 Ridge/XGBoost，不另建基线。

**动作：**

1. 在首次训练前冻结特征、Fisher 权重、容量、正则和 train-only 选择空间。
2. 科学评估阶段对 `10/25/50/75/100%` 嵌套 group 前缀各运行一次 Ridge、PLS、ELM、PLSELM、XGBoost、FO-MPLSELM 与轻量 CNN，用于 reference 选择、learning curve、RMSE、P90 和逐样本预测；不得以计时为理由重复生成同一科学预测。
3. 正式计时阶段只使用 `100%` train group，并只对 FO-MPLSELM 与该 split × seed 下由 validation 选出的 reference 执行 30 次配对随机交错训练计时和 `1/32/256` 三个 batch size 的推理计时。其他比例和未入选模型只保留首次科学拟合的分阶段耗时，不进入正式 timing CI。
4. 训练 wall-clock 固定为 `preprocess + fit + validation`；FO-MPLSELM 的 Fisher 权重计算属于 preprocess，不得移出成本口径。所有配对行必须绑定相同的 CPU/GPU 轨、线程、软件、Git 与硬件指纹。
5. val/test group 在所有比例保持不变；不同数据比例不得重新抽样。特征、train/val 索引、标签和样本级 Fisher 可以按冻结身份缓存，但不得缓存或提前打开 test label 参与 reference 选择。
6. 执行随机正交方向、移除 Fisher 权重与随机非嵌套子集负对照。前两项对每个组分按 `control P90 - candidate P90` 的 mixture-group 配对 CI 判断机制证据；随机非嵌套子集只用于 train-only 与泄漏检查，不进入优势结论。
7. 若 FO-MPLSELM 与普通 PLSELM 在冻结数值容差内等价，明确判 reject，不以重新命名构成创新。
8. attempt 以 `split_id × seed × training_fraction` 为最小 checkpoint 单元。每个完成单元原子写入 payload hash；resume 必须逐项核对 config、pilot manifest、代码、环境、线程和硬件身份，身份漂移时拒绝续跑。
9. 中断保留已完成 checkpoint，不生成 `status=complete` manifest。恢复时只跳过 hash 校验通过的完成单元；单元内中断则完整重跑该单元，不拼接部分 timing。
10. 每完成一个单元报告 `completed/total`、累计耗时和 ETA。科学评估可在线程限制明确且不写共享结果文件的前提下并行；正式计时必须单进程、idle system 串行执行。
11. 10,000 次 paired group bootstrap 对等长 mixture group 使用批量向量化索引；非等长 group 使用带有效位掩码的分批向量化路径。两条路径都必须固定 seed、以 `mixture_id` 为重采样单位，并通过确定性与标量参考结果一致性测试。

**冻结执行量：** 75 个科学单元共 525 次主模型拟合；100% fraction 的候选与入选 reference 增补 870 次计时拟合；负对照 225 次，总计 1,620 次 fit。正式推理计时为 108,000 次 `predict` 调用。数量变化只能来自显式修改本任务卡并重新冻结执行配置，不能由运行时自行裁剪。

**验收命令目标：**

```powershell
python -m gib.cli run-data-efficiency --config configs/p3_c5b_data_efficiency_plan.json --pilot-freeze outputs/archive/freezes/GIB-FREEZE-P3-PILOT-20260825-02 --execution-registry configs/p3_execution_registry.json --git-commit <commit> --attempt-dir outputs/runs/attempts/<attempt_id>
python -m gib.cli run-data-efficiency --config configs/p3_c5b_data_efficiency_plan.json --pilot-freeze outputs/archive/freezes/GIB-FREEZE-P3-PILOT-20260825-02 --execution-registry configs/p3_execution_registry.json --git-commit <same_commit> --attempt-dir outputs/runs/attempts/<same_attempt_id> --resume
```

**通过：** 满足 NI，且首次达标比例不高于 75%，或训练 wall-clock/batch-size-1 latency 至少下降 20%；其他 primary cost 满足 NR5。

**终态：** `enter_P4`、`reject` 或 `inconclusive`；只在单比例或单 seed 有效不得通过。

### P3-09 · C4 可辨识共享 / 私有多视图表示

**输入：** P2-07 `eligible_for_P3_test`、冻结 Raw/DSP 多模态数据、G3-3 baseline。

**允许修改：** 相同 encoder 容量下的 early fusion、共享/私有分支和同参数量随机分组实现；OOD 配置必须在首次训练前冻结。

**动作：**

1. 冻结遮蔽 OOD 与未见 nuisance OOD 的构造、训练/验证/测试访问规则，并分别报告，禁止合并成一个 OOD 数。

**通过：** OOD MAE 相对 early fusion 下降至少 10%，95% paired CI 支持，且完整模态 R² 回退不超过 0.01。

**终态：** 随机分组不劣、共享表示不可线性探测或只改善完整模态时 `reject`；不得通过扩大容量补救。

### P3-10 · C2-IC-RDU-VP 条件式最小实现

**激活条件：** 仅当 P3-06 `c2_preflight=pass`。否则记录 `candidate_verdict=not_activated`，不得实现展开网络。

**允许修改：** 信息条件化正则、可学习更新、自适应深度及其独立开关；禁止超出最小实现的容量搜索。

**终态：** `enter_P4` 或 `reject`；该 verdict 只授权 P4 继续验证，不证明现实设备优势。

### P3-13 · G3-4 候选晋级评审

**输入：** P3-06 至 P3-12 的冻结证据、P2 候选矩阵和 S4 联合门。

**允许修改：** `docs/p3/P3候选晋级记录.md`、只从 freeze 派生的 summary/report、G3-4 freeze。禁止重跑或改门补结果。

**动作：**

**激活条件：** G3-4 `pass`。

**允许修改：** `p3_formal_dataset_plan.json`、生成/打包性能实现和 dry-run 测试。禁止改变前向 profile、信息档、split、seed 和字段语义。

**动作：**

### P3-15 · G3-5 正式数据生成、打包与冻结

**输入：** G3-4 freeze、`p3_formal_dataset_plan.json`、通过验证的生成链。

**动作：**

1. 按冻结计划生成全部 9 格，不允许只扩充候选优势单元。
2. 固定 5 个 group split 和 3 个训练/eval seed；所有方法共享相同数据身份。

5. 验证 oracle 隔离、Raw → DSP hash、profile hash 和代码 hash。

8. 任何生成异常、hash 不符、split 泄漏、profile 漂移或 oracle 泄漏都使本 attempt 失败；修正后创建新 attempt。

**通过：** 正式 freeze 覆盖 9/9 单元，所有 artifact hash、schema、split、provenance 和泄漏检查通过。

**失败：** `gate_verdict=fail`，不得发布数据或关闭 P3；修生成/打包链后新建 attempt。

### P3-16 · P3 关闭评审与 P4 交接

**输入：** G3-1 至 G3-5 freeze、候选晋级记录、正式数据 freeze、P3 状态页。

**允许修改：** `docs/p3/P3评审记录.md`、`docs/p3/README.md` 和总体规划中的阶段状态；禁止在关闭任务中产生新实验结果。

**评审清单：**

1. G3-1 前向与全部负对照通过。
2. G3-2 9/9 单元达到信息档和夹角档。
3. G3-3 pilot 完整、oracle 隔离、强基线空档充分。
4. G3-4 所有 active 和被触发 conditional 路径达到终态，至少一个候选晋级。
5. G3-5 正式数据 freeze 可独立验证。
6. 所有候选使用同一 controlled synthetic profile、split、seed、预算和硬件指纹。
7. 没有 legacy 主键、静默 fallback、失败删行、oracle 泄漏或 freeze 覆盖。
8. 结论明确限定为同条件合成相对比较，没有目标硬件绝对性能声明。
9. P4 交接只包含晋级候选；未晋级候选不得以“备选实现”进入 P4。

**最终 verdict：**

- `p3_verdict=pass`：P3 关闭，允许 P4-4A 基线复现与晋级候选开发；
- `p3_verdict=return_to_P1_P2`：科学门未通过，记录根因与返回任务，不进入 P4；
- `p3_verdict=blocked`：仅限外部运行条件无法取得，P3 保持未关闭。

## 7. 每个任务的标准执行循环

每次只推进一个任务状态，执行记录追加到 `docs/p3/README.md`：

1. 写明 `task_id`、输入 freeze/hash、允许修改范围和预期 verdict。
2. 先运行目标单测；失败先定位根因。
3. 实现单一所有者能力，不复制 schema、门值、split 或指标逻辑。
4. 运行正例、负对照和失败路径。
5. 长任务按任务卡定义的原子 checkpoint 单元执行；resume 只接受完整身份匹配和通过内容 hash 校验的单元。
6. 运行子工程全量测试，默认单元测试超时 60 秒。
7. 检查 diff：重复逻辑、静默 fallback、吞错、legacy 键、oracle 泄漏和未说明行为变化。
8. attempt 完整后才写 `status=complete` 并 freeze；freeze 后立即独立 verify。
9. 追加实际命令、退出码、关键计数、verdict、失败证据和 `next_allowed_task`。

建议执行记录格式：

```text
task_id: P3-XX
status: completed | failed | blocked
input_freezes:
  - <freeze_id> | evidence_manifest_sha256=<sha256>
changed_files:
  - <path>
commands:
  - <command> | exit=<code>
evidence:
  - <metric_or_check>=<value>
verdict:
  gate_verdict: pass | fail
  candidate_verdict: enter_P4 | reject | not_activated | inconclusive
scope:
  - controlled_synthetic_relative_comparison_only
next_allowed_task: <task_id | none>
```

不适用字段写 `not_applicable`，不得省略后让读者猜测。

## 8. 验证矩阵

| 验证层 | 最低要求 | 执行节点 |
|---|---|---|
| 单元测试 | 公式、ID、split、schema、I/O、统计、候选核心机制各有正负例 | 每个任务 |
| 契约测试 | legacy 键拒绝、oracle 拒绝、Raw/DSP provenance、freeze 不覆盖 | P3-03 起每次全量 |
| 门值测试 | NI/E30/E20/NR5、C4 OOD、G3-3 gap 的边界值和缺失值 | P3-05 起 |
| 失败路径 | 非收敛、缺指标、硬件不匹配、split 泄漏、hash 漂移均显式失败 | 对应任务 |
| CLI 冒烟 | 每个新增命令至少一次最小成功和一次预期失败 | 每个 CLI 任务 |
| 全量测试 | `python -m pytest -q` | 修改共享契约或关闭阶段 gate 前 |
| 候选冒烟 | 目标 runner 完成、结果字段齐全、无 failed rows | 单候选修正与重跑 |
| freeze 校验 | `python -m gib.cli verify-freeze <freeze_dir>` 返回全部通过 | G3-1 至 G3-5 |
| 文档一致性 | 任务状态、freeze、verdict、下一任务一致；链接可解析 | P3-13、P3-16 |

## 9. 里程碑与资源顺序

| 工作包 | 内容 | 预计关键路径 | 退出条件 |
|---|---|---:|---|
| W1 | P3-00 至 P3-02 | 1 周 | G3-1/G3-2 pass |
| W2 | P3-03 至 P3-04 | 1–2 周 | pilot integrity pass 并冻结 |
| W3 | P3-05 | 1 周 | G3-3 baseline_sufficient |
| W4 | P3-06 至 P3-09 | 2–3 周 | 所有 active 路径终态 |
| W5 | P3-10 至 P3-12 | 0–2 周，按激活门 | 被触发 conditional 路径终态 |
| W6 | P3-13 | 2–3 天 | G3-4 pass 或正式返回 P1/P2 |
| W7 | P3-14 至 P3-15 | 1–2 周 | G3-5 正式数据 freeze |
| W8 | P3-16 | 2–3 天 | P3 关闭 verdict |

以上是依赖顺序和资源估计，不是结果承诺。P3 预留一轮 bench/生成链返工时间；返工只能沿任务卡的显式返回路径进行，不能在下游加补丁绕过上游失败。

## 10. P4 交接的最小内容

只有 P3-16 `pass` 后，P4 才接收：

1. 正式数据 freeze ID 与 evidence manifest hash；
2. 晋级候选 ID、机制、适用单元和 `enter_P4` 证据；
3. 配对 baseline、split、seed、硬件和预算配置 hash；
4. 必做消融和负对照列表；
5. 未晋级候选及停止原因；
6. controlled synthetic 的声明边界与 P5 真实硬件待办。

P4 的首个动作是 4-A 对冻结数据和 baseline 的复现，不是修改 P3 门值或直接扩大晋级模型。
