## 1. 背景与依据

### 1.1 Phase-aware N2 第一轮结论

`phaseaware_best_models` 实验（test split）关键数据：

| 路线 | 窗口 | test N2 R² | 其他组分最大 R² drop | 验收 |
|---|---|---:|---:|---|
| ML | full baseline | 0.2173 | 0（基准） | — |
| ML | exposure | **0.6014** | 0.0726 | ❌ 其他组分超阈值 |
| ML | recovery | 0.5767 | 0.0490 | ✅ 仅差 0.001 到阈值 |
| ML | early 0.75 | 0.3465 | 0.0004 | ✅ N2 偏弱 |
| DL | 所有窗口 | ≈ 0 | — | ❌ |

阈值：N2 gain ≥ 0.10、其他组分 R² drop ≤ 0.05、macro RMSE 不退化、extrapolation margin ≥ -0.10。

### 1.2 核心矛盾

窗口在 ML pipeline 里的作用（`src/ml/features.py:243-262`）：phase/early 生成 timestep mask，**只用被选中时间步**计算统计量，四个组分共用这一套特征喂给单个 multi-output ridge。

矛盾出在「共用」：裁到 exposure 窗口，N2 拿到动态信号（R² 0.60），但 H₂/CH₄/CO₂ 被迫丢掉稳态信息 → 掉 0.073。**单一全局窗口逼所有组分共享同一取舍**，而不同组分的信息分布在不同相位。recovery 勉强过线只是恰好踩在折中点，0.001 的余量太脆。

### 1.3 已排除方向：log-ratio（ILR/ALR）

formal_full 全窗口结果（test x_N2 R²）：

| 配置 | 目标空间 | test N2 R² |
|---|---|---:|
| ridge_all_modalities | 原始 | 0.2173 |
| ridge_ilr_n2_first | ILR | 0.1058（更差） |
| ridge_alr_ch4 | ALR | 0.1058（更差） |
| cnn1d_tcn_fusion | 原始 | -0.0075 |
| cnn1d_tcn_fusion_ilr | ILR | -0.0916（更差） |

log-ratio 把其他组分误差通过比值耦合进 N2 坐标，对「单独抬弱信号 N2」是负担。该路线判定为负向，不再投入。

## 2. 方案设计

### 2.1 思路：特征装配从「替换」改「拼接」

```
现状：window → 单一 mask → 一套统计量(约 140 维) → ridge
改后：windows = [full, exposure, recovery]
      → 各自 mask → 各自统计量 → 横向拼接(约 420 维，加窗口前缀) → ridge
```

裁剪是做减法（丢信息换信噪比），拼接是做加法（保留全部，让模型选）。ridge 的 L2 正则 + 线性权重让每个组分自选用哪个窗口的特征：

- N2 取 exposure/recovery 段的动态特征；
- H₂/CH₄/CO₂ 保留 full 段的稳态特征，不被迫退化。

这直接拆掉「exposure 对 N2 最好但伤其他组分」的取舍。

### 2.2 维度与过拟合

每窗口特征 ≈ slow(8×7) + ultrasonic(6×7) + fiber(6×7) ≈ 140 维，3 窗口 ≈ 420 维。train split 约数千行，n ≫ p，α=1 正则足够，无过拟合风险。

### 2.3 数据流不变量

各窗口在同一 split 上按相同 sequence 顺序加载，`y` / `label_names` / `sequence_ids` 三者一致；拼接只在特征列方向发生。

## 3. 改动清单

全部在 ML 侧，4 处。**单窗口路径零改动**（`feature_windows=None` 时走原逻辑），现有 5 个 run 行为不变。

### 3.1 `src/ml/features.py`（核心）

1. `MLFeatureConfig` 新增字段：
   ```python
   feature_windows: tuple[WindowConfig | None, ...] | None = None
   ```
   从 `common.windows` 导入 `WindowConfig`（无循环依赖，features.py 已依赖 common.scalers/splits）。

2. `load_feature_matrix` 开头加分支：
   ```python
   if config.feature_windows is not None:
       return _load_multiwindow_feature_matrix(dataset_dir, split=split, config=config)
   # 否则保持现有单窗口逻辑
   ```

3. 新增 `_load_multiwindow_feature_matrix`：
   - 对每个 `w in config.feature_windows`：
     - 用 `dataclasses.replace` 造单窗口子 config：`feature_windows=None`，按 w 类型填 `phase_filter`（phase）或 `early_fraction`（early），`w is None` 表示 full（两者都 None）；
     - 递归调用 `load_feature_matrix` 拿到该窗口的矩阵；
     - 给 `feature_names` 加窗口前缀；
   - 横向 `np.concatenate` 所有 `x`，合并 names；
   - `y` / `label_names` / `sequence_ids` 取第一个窗口的；
   - 返回 `MLFeatureMatrix`。

4. 新增 `_window_tag(w) -> str`：`None→"full"`、phase→`f"ph_{value}"`、early→`f"early_{value:.2f}"`。前缀形如 `full|slow:temp:mean`、`ph_exposure|...`、`ph_recovery|...`。

### 3.2 `src/pipeline/experiment_config.py`（校验）

1. `_validate_run_dict`：ML run 允许 `windows`（list，元素为 window 对象或 `null`=full），逐个过 `resolve_window_config`（`null` 跳过）。
2. 互斥校验：`windows` 不得与 `window` 或 `protocol` 同时出现，命中即明确报错。
3. 修空列表陷阱（166-167 行）：
   ```python
   # 现状：空 list 被 or 当成 falsy 回退全量默认
   ml_runs = tuple(payload["ml_runs"] or DEFAULT_ML_RUNS)
   dl_runs = tuple(payload["dl_runs"] or DEFAULT_DL_RUNS)
   # 改为：键存在且非 None 就用它（哪怕空），让 dl_runs:[] 真正表示「不跑 DL」
   ```
   实现前先 grep 确认无现存配置依赖 `[]`→默认这一行为。

### 3.3 `src/pipeline/run_experiment.py`（装配与汇总）

1. `_run_ml`：读 `run_config.get("windows")`，存在时构造带 `feature_windows` 的 `MLFeatureConfig`（`phase_filter=None, early_fraction=None`）。
2. summary 的 `window` 列：多窗口时写标签 `multi:full+exp+rec`（新增分支，不碰单窗口路径）。
3. `_training_payload` 的 `feature_config` 补记 `feature_windows`，使 run 自描述。

### 3.4 新建 `configs/experiment/multiwindow_n2/multiwindow_n2.json`（ML-only 实验）

- `dl_runs: []`（依赖 3.2 的空列表修复）。
- `ml_runs`：
  - `ridge_all_modalities`（`protocol:false`，full baseline，自包含同数据集对照）；
  - `ridge_multiwindow_all_modalities`，`windows: [null, {"kind":"phase","value":"exposure"}, {"kind":"phase","value":"recovery"}]`。

## 5. 验收标准

相对 `ridge_all_modalities` full baseline（test split）：

- N2 R² gain ≥ 0.10
- 其他三组分 R² drop ≤ 0.05
- macro RMSE 不退化
- extrapolation N2 R² margin ≥ -0.10

**预期落点**：N2 R² 0.55–0.60，其他组分 drop ≈ 0，余量较 recovery 的 0.001 显著拉开。

---

## 6. 判定与后续

- **N2 ≥ 0.57 且 other-drop ≈ 0** → 多窗口拼接成为正式 ML phase-aware 主线，取代脆弱的 recovery 单窗口；写入正式配置与论文结果引用。
- **N2 明显低于 exposure 单窗口(0.60)** → 拼接稀释了信号，转备选方案 B：分组分独立 regressor（N2 用 exposure 特征，其他用 full 特征）+ 闭包归一化到 100%。
- **窗口边界细化（方案 C）**：在主方案跑通后，作为增量调参（更窄/过渡段窗口），优先级最低。
- DL 不在本计划内。DL 的 N2≈0 来自输出头（N2 为闭包残差）+ MSE 尺度，与窗口无关；DL phase-aware 需先改输出头，属另一条线。

## 7. 风险与回退

- 改动集中在 ML 特征装配，单窗口路径不变，现有 5 个 run 行为不受影响。
- 唯一共享代码改动是空列表回退修复（3.2），低风险，实现前以 grep 确认。
- 全程本机 ridge 秒级可验证，无机时成本；失败可直接删除新配置与新增分支回退。

## 8. N2 天花板说明

N2 惰性、红外不吸收，无直接信号。full=0.22 → 窗口=0.60，窗口已把它翻近 3 倍。多窗口拼接大概率稳住 0.60 一档并通过验收；想再大幅上行（如 0.8+）单靠窗口/特征工程很难，需更强物理特征（声速、密度对 N2 的间接依赖显式建模）或接受惰性气体的固有上限。
