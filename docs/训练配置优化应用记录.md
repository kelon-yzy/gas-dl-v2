# 训练配置优化应用记录

## 优化参数

| 参数 | 原值 | 优化值 | 变化 | 理由 |
|------|------|--------|------|------|
| `epochs` | 300 | **80** | -73% | MVP 4 epoch 收敛，300 完全浪费 |
| `batch_size` | 8/16 | **32** | +2-4× | 提升 GPU 利用率，降低 kernel overhead |
| `num_workers` | 8 | **2** | -75% | 减少 Windows 多进程 CUDA context 开销 |
| `persistent_workers` | true | **false** | 关闭 | 释放常驻进程显存 |
| `lr` | 0.0001-0.0005 | **0.0002-0.001** | +2× | batch size 增大，学习率线性缩放 |
| `early_stopping.patience` | 25 | **10** | -60% | 更激进的早停，减少无效训练 |

## 学习率调整说明

不同配置文件的学习率根据原始 batch size 进行缩放：

| 配置文件 | 原 batch size | 原 lr | 新 batch size | 新 lr | 缩放逻辑 |
|---------|--------------|-------|--------------|-------|---------|
| phase_window_tcn_mvp_optimized | 8 | 0.0005 | 32 | 0.001 | 4× batch → 2× lr (保守) |
| phase_window_tcn_ablation | 16 | 0.0001 | 32 | 0.0002 | 2× batch → 2× lr (线性) |
| phase_window_tcn_ablation_* | 16 | 0.0001 | 32 | 0.0002 | 2× batch → 2× lr (线性) |
| phase_window_tcn_improvement | 16 | 0.0001 | 32 | 0.0002 | 2× batch → 2× lr (线性) |

**原理**: 标准做法是线性缩放（batch 增大 k 倍 → lr 增大 k 倍），但从 8 → 32 采用保守缩放（2× 而非 4×），避免过大学习率影响收敛。

## 回退方案

如果优化后仍出现问题：

1. **显存 OOM**: 降低 batch_size 到 24 或 16
2. **收敛变差**: 降低 lr (例如 ×0.8)
3. **数据加载慢**: 增加 num_workers 到 4（注意显存）

## 验收标准

与原配置在**相同 seed** 下对比：
- `val_loss` 误差 < 5%
- `test x_N2 R2` 误差 < 0.05
- 训练时长降低 > 50%
- 显存占用 < 12GB

## 注意事项

1. **Windows 环境特殊性**：
   - spawn 多进程而非 fork
   - 每个 worker 独立内存空间
   - num_workers 过多会导致显存爆炸

2. **学习率缩放**：
   - 配合 ReduceLROnPlateau 自适应调整
   - 观察前几个 epoch 的 loss 曲线
   - 如有震荡可降低 lr

3. **Early stopping**：
   - patience=10 已比较激进
   - 如发现过早停止可调回 15-20

4. **AMP (自动混合精度)**：
   - 已启用 float16 AMP
   - 进一步加速训练
   - 不影响最终精度
