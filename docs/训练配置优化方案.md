# 训练配置优化方案

## 问题分析

### 原始配置瓶颈
- **训练时间**: 每 epoch ~248秒，完整训练约 2 小时
- **显存占用**: 17GB（RTX 5880 24GB）
- **吞吐量**: ~17.6 samples/s
- **GPU 利用率**: 极低（模型实际只用 163MB）

### 根本原因
1. **Batch size 过小** (8)：GPU 并行度不足，kernel launch overhead 高
2. **多进程开销** (8 workers)：Windows 环境下每个 worker 独立 CUDA context
3. **persistent_workers=true**：常驻进程占用显存
4. **Early stopping 太晚** (patience=25)：MVP best_epoch=4，实际跑了 29 epochs

## 优化方案 1（已实施）

### 配置变更

| 参数 | 原值 | 优化值 | 理由 |
|------|------|--------|------|
| `batch_size` | 8 | **32** | 提升 GPU 利用率，4× 并行度 |
| `num_workers` | 8 | **2** | 减少多进程 CUDA context 开销 |
| `persistent_workers` | true | **false** | 释放常驻进程显存 |
| `lr` | 0.0005 | **0.001** | batch size 增大需线性缩放学习率 |
| `epochs` | 300 | **80** | MVP 4 epoch 收敛，300 完全浪费 |
| `early_stopping.patience` | 25 | **10** | 更激进的早停，减少无效训练 |

### 预期效果

**显存占用**：
- 原配置: 17GB
- 优化后: **6-8GB**（降低 60%）

**训练速度**：
- 每 epoch: 248s → **60-80s**（加速 3-4×）
- 吞吐量: 17.6 → **60-80 samples/s**
- 完整训练: 2 小时 → **15-25 分钟**（加速 5-8×）

**Phase 1 诊断批次**（3 个实验）：
- 原配置: ~6 小时
- 优化后: **1-1.5 小时**

## 收敛性保障

### 学习率缩放
- Batch size 增大 4× → lr 增大 2×（保守缩放）
- 使用 ReduceLROnPlateau scheduler 自适应调整

### 早停机制
- patience=10 相比原 25 更激进
- 但 MVP best_epoch=4，10 已足够宽裕

### 验收标准
与原配置在**相同 seed** 下对比：
- val_loss 误差 < 5%
- test N2 R² 误差 < 0.05

## 可选优化方案 2（更激进）

如果方案 1 显存仍紧张或需要更快：

```json
{
  "batch_size": 48,
  "num_workers": 0,
  "pin_memory": false,
  "persistent_workers": false,
  "lr": 0.0015
}
```

**适用场景**: 数据加载快（memmap），CPU-GPU 传输不是瓶颈时。

## 环境变量优化（可选）

限制 PyTorch CUDA 缓存池：

```bash
export PYTORCH_CUDA_ALLOC_CONF=max_split_size_mb:512
```

或 Windows PowerShell:
```powershell
$env:PYTORCH_CUDA_ALLOC_CONF="max_split_size_mb:512"
```

## 回退方案

如果优化后出现：
1. **显存仍 OOM**: 降低 batch_size 到 24 或 16
2. **收敛变差**: 降低 lr 到 0.0008 或 0.0006
3. **数据加载慢**: 增加 num_workers 到 4（但注意显存）
