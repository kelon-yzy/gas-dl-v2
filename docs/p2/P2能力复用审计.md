## 1. 分类规则与审计结论

- `可直接迁移`：符号本身是场景无关的纯函数或流程契约；迁移方式仍是复制到新所有者并改命名空间，不从历史包导入。
- `需解耦`：符号含有 HG、SG 或 TV3 私有导入、气体字段、MRS 观测、场景路径或场景常量；只能提取不变量并在新所有者中重写接口。
- `不得复用`：旧主键语义、旧 ID 前缀、场景常量、历史 verdict、历史 freeze 路径或已废弃字段；这些内容只能作为审计证据，不能进入新 bench 运行时。

结论：现有来源可以迁移契约不变量和少量纯函数，但没有可直接作为新 bench 公共库的完整实现。新子工程必须建立自己的 `sim/core`、`sim/packaging`、`sim/validation`、`audit` 和 freeze 入口。

## 3. 效率能力缺口（必须保留为未具备）

现有 `S1Iteration` / `VarProSolution` 能提供 iterations、forward calls、stop reason、condition number、residual、convergence 和 bound hit；`_domain_metrics` 能提供按旧 domain 的均值与 paired bootstrap 对比。但现有来源没有满足 P2 新协议的统一 wall-clock、训练预处理/fit/validation 分段、warm-up 后推理延迟、批量吞吐、嵌套 mixture group 数据效率或新增时间窗/采样点/模态的增量信息及 `Delta I / Delta cost`。

因此 P2-08 必须在新 metric registry 中重新定义计时与成本字段，不能把旧 `mean_iterations` 或一次本机计时替代 wall-clock 协议，也不能把旧 B4 的 paired bootstrap 直接视为完整效率证据。

## 4. 禁止迁移字段说明

新正式 benchmark 禁止下列历史字段进入 schema、manifest、loader、split 或报告；以下是本审计文档中唯一列出这些字段的说明位置：`base_condition_id`、`noise_seed_index`、`noise_seed`。它们不是新主键、分组键或可选兼容字段；缺失时必须失败，不得回退、别名化或静默重写。
