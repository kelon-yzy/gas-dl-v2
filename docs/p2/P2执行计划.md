## 0. 给执行模型的使用说明

本计划按“低自主度”编写。执行模型一次只能领取一个任务卡，不得把多个任务合并完成。

每次执行都必须遵守以下顺序：

1. 只读取当前任务卡列出的输入文件。
2. 用 3–6 句话复述任务目标、禁止事项、允许修改的文件和验收方式。
3. 检查前置任务的交付物与 verdict；前置未通过时停止，不得假设通过。
4. 只修改“允许修改”列出的文件。发现必须改其他文件时，先停止并记录原因。
5. 运行任务卡中的验收命令。
6. 在任务记录中写入：修改文件、命令、退出码、关键结果、未解决项、verdict。
7. verdict 只能从任务卡给出的枚举值中选择，不得自造“基本通过”“暂时可用”等状态。

禁止行为：

- 不得把 `mixture_id` 回退、别名化或重写为 `sequence_id`。
- 不得在新正式 benchmark 中引入 `base_condition_id`、`noise_seed_index`、`noise_seed`。
- 不得从新子工程跨目录导入 `hg`、`sg`、`tv3` 或 `rcdw` 私有包。
- 不得复制整个历史子工程后再删除无关内容。
- 不得把 C1 写成“首次使用信息论、Fisher 或 CRB”；C1 是 T2 组合评估框架，不是算法候选。
- 不得把 C2、C4 或待授权的 C5 写成已晋级算法；C3 不占 G3-4 名额。
- 不得静默修改 P1 冻结候选集中的门值。
- 不得用 oracle 真值特征训练可部署模型，不得用测试真值调参。
- 不得生成 pilot 或正式数据，不得启动深度模型训练。
- 不得手工把运行数值誊写进正式报告；正式数值必须由脚本从冻结产物生成。
- 不得吞掉异常、伪造空文件、mock 成功或用默认值绕过缺失字段。

## 1. Context / Task / Format

### 1.1 Context

P1 已关闭，但 2026-08-24 的关闭后审查改变了 P2 的任务排序：

- C1 继续作为信息谱评估框架，不参与 G3-4 算法晋级。
- C2 的主收益轴应从单纯精度改为同精度下的迭代数与 wall-clock；原门值不能直接改，必须走显式修订。
- C5 是待新增的效率类候选；未经授权不能进入正式晋级矩阵。
- 信息量与 target–nuisance 可分离性是两个独立坐标；bench 必须同时提供信息量三档和 Jacobian 夹角三档。
- C4 只有在跨模态互补性先被前向审计证明后才有实验对象。
- C3 只留给 P5 真实硬件阶段，不在纯仿真 bench 上争取 G3-4 名额。

### 1.2 Task

P2 要交付一份可直接约束 P3 实现的 bench 规格书，并证明该规格在纯前向层面可实现。规格必须回答：

1. 目标量 `theta`、nuisance `eta`、观测模态和工作域分别是什么。
2. 如何独立调节信息总量与 target–nuisance Jacobian 夹角。

4. 四组分系统如何满足光学可见、声学或热导可见、跨模态消歧和低浓度目标四项要求。

7. 新子工程的命名空间、schema、文件布局、所有权和禁止依赖是什么。
8. P3 的 G3-1 至 G3-5 如何消费这些契约，尤其是 G3-3 与 G3-4 的停止条件。

## 2. P2 完成定义

只有以下条件全部满足，P2 才能标记为完成：

- S1–S6 各有独立章节、字段、公式、配置项和验收项。
- 信息量 `sufficient / critical / insufficient` 三档均有可复算的 Fisher、CRB 和目标误差 P90 预期范围。
- Jacobian `high / medium / low collinearity` 三档与信息量档正交设计，形成 3 × 3 审计矩阵。
- 四组分与传感器方案通过 S2 纯前向筛选；未通过时不得靠增加网络复杂度补救。
- pilot 数据契约包含样本级 Fisher/CRB、增量信息、solver difficulty、Raw + DSP 双数据层。
- 训练、推理、求解器和采样的效率测量协议可重复，且不依赖单次计时。
- C2 修订和 C5 新增已有显式授权记录；若未授权，规格必须保持 `pending_authorization`，P2 不得通过终审。
- 新子工程的目录、包名、schema、ID 前缀和代码所有权已冻结。
- 复用审计逐个符号给出“可直接迁移 / 需解耦 / 不得复用”及证据。
- P3 G3-1 至 G3-5 的输入、输出、通过、失败和停止路径均可达。
- 设计评审 verdict 为 `pass`，不存在“以后再补”的必填项。

P2 完成不代表：bench 已有数据、任何算法已优于基线、C2/C4/C5 已晋级、或最终工业应用已经选定。

### P2-04 · 参数、组分和观测模态登记

**输入：** 总体规划 §6.1–§6.3、工业调研 §2.1、算法调研 §6。

**允许修改：** `docs/p2/P2_bench规格书.md` 的“科学问题”“参数登记”“候选体系”章节；H2 通过后可新增只含配置 schema 的文件，不得生成数据。

**操作：**

1. 用统一模型登记 `y = F(theta, eta; design) + epsilon + delta`。
2. `theta` 只含目标组分；`eta` 至少登记 T、P、RH、声程 L、传感器 gain、baseline、delay、crosstalk。
3. 每个量登记名称、单位、工作范围、先验、是否可观测、是否允许进入部署模型、来源。
4. 首选低风险候选固定从 `N2/CO2/O2/Ar` 四组分开始；备选可为含 CH4 的体系，但必须先有独立安全门。不得把 H2/CO/CH4 体系默认为首个实验载体。
5. 首选模态至少含 NDIR、超声原始波形、声学 DSP、热导、T/P/RH/flow 慢通道。
6. 写明闭包处理：若四组分和为 100%，Fisher 参数化只使用三个自由坐标，但输出与报告仍按四个物理组分命名；不得把闭包组分当作无误差背景值。

**验收：** 至少四组分；目标与 nuisance 无重名；单位齐全；每个传感器都能映射到一个前向观测；安全条件不明的方案只能作为备选。

**verdict：** `ready_for_forward_screen` 或 `revise`。

### P2-05 · 纯前向候选筛选

**输入：** P2-04 登记；物理常数、传感器频响、噪声和器件来源。

**允许修改：** 新子工程中的纯前向 audit 最小实现及其测试；`docs/p2/P2_bench规格书.md` 的候选筛选表。禁止数据生成器和训练代码。

**操作：**

1. 对每个候选体系计算白化 Jacobian `J_theta`、`J_eta`、联合秩、有效 Fisher 和 CRB。
2. 有 nuisance 先验时用 Schur complement 计算目标有效信息；不得只反演 `J_theta.T @ W @ J_theta` 后声称已边缘化 nuisance。
3. SVD 秩结论必须在相对容差 `1e-7 / 1e-6 / 1e-5` 下同向。
4. 运行单组分扰动、总量缩放、模态关闭、噪声单调性四类负对照。
5. 对每个组分输出分模态灵敏度、分模态有效信息占比和组分对相似度。
6. 若首选体系不能满足 S2，记录失败机制后评审备选；不得先加模型掩盖物理缺口。

**验收：** 同一配置可重复得到相同结果；噪声增大时 CRB 不得改善；增加有效模态时信息不得无解释下降；所有负对照有明确期望与实际值。

**verdict：** `candidate_selected`、`redesign_required` 或 `physics_source_blocked`。

### P2-06 · 冻结信息量与 Jacobian 夹角 3 × 3 刻度

**输入：** P2-05 选定体系及前向 audit。

**允许修改：** 规格书的 S1 章节和信息档配置；纯前向 audit 测试。

**操作：**

1. 先为每个目标组分冻结容许误差 `tau_j` 及来源。
2. 用 `r_j = CRB_P90_j / tau_j` 定义信息档。默认候选区间为：`sufficient: max(r_j) <= 0.5`，`critical: 0.8 <= max(r_j) <= 1.2`，`insufficient: max(r_j) >= 2.0`。若修改区间，必须在看到 pilot 结果前写明理由。
3. 用白化后的 `J_theta` 与 `J_eta` 子空间最小主夹角定义共线档。默认目标中心为高共线 `10 deg`、中共线 `45 deg`、低共线 `80 deg`，每档容许偏差 `±5 deg`。
4. 信息量主要通过模态、噪声、先验宽度和组分窗口调节；夹角通过已登记的 nuisance 耦合参数调节。不得用同一个无解释噪声倍数同时冒充两个轴。
5. 形成 9 个单元的表，每格登记配置 ID、实际 Fisher、CRB P90、实际主夹角、条件数和可达性。
6. 任一档不可达时回到 P2-04/P2-05 修改物理设计，不得把空格留给 P3。

**验收：** 三个信息档有间隔且单调；三个夹角档达到目标容差；在固定信息档内改变夹角时总信息尺度变化必须报告并受限；9 格全部可复算。

**verdict：** `grid_frozen` 或 `redesign_required`。

### P2-07 · S2 模态互补与 S3 空档开关

**输入：** P2-06 的 9 格审计结果。

**允许修改：** 规格书 S2、S3；对应配置和纯前向测试。

**操作：**

1. 为四项 S2 要求各指定一个具体组分或组分对，并给出量化证据：光学主可见、声学或热导主可见、单模态近简并但跨模态可分、低浓度目标。
2. 冻结近简并和消歧阈值；阈值必须基于白化灵敏度或增量有效信息，不得凭波形图肉眼判断。
3. 为三个 headroom 来源建立独立开关：`fast_waveform`、`nonlinear_nuisance_coupling`、`cross_sensitivity`。
4. 对每个开关写出 `on`、`off` 唯一差异、预期变化、不应变化的量和失败解释。
5. 证明三个开关可单独关闭；同时关闭只作负对照，不得作为目标档位。

**验收：** 每项 S2 有具体对象和数值证据；每个 S3 开关只改变一个机制；C4 前置 verdict 明确为 `eligible_for_P3_test` 或 `no_complementarity`。

**verdict：** `pass` 或 `redesign_required`。

### P2-08 · S4 精度与效率测量协议

**输入：** P1 原门与已授权修订、算法调研 §3、总体规划 §6.4。

**允许修改：** 规格书 S4 和 metric registry。禁止运行正式模型比较。

**操作：**

1. 精度侧固定四层：CRB、oracle、测量级 DSP、强基线。oracle 与部署结果必须分表。
2. 强基线至少预注册 Ridge、GBDT 和一个强表格模型；深度基线只允许固定容量 MLP/TCN，不得边看结果边增容。
3. 固定 5 个 `mixture_id` group split × 3 个 seed；所有候选使用相同 split、样本和预算。
4. 训练计时分为预处理、fit、validation；推理计时先 warm-up，再记录批量吞吐与单样本延迟。
5. 求解器至少记录 iterations、forward calls、convergence、condition number、final residual、runtime；runtime 用单调时钟，记录硬件、线程数、软件版本和重复次数。
6. 数据效率使用嵌套的 `10% / 25% / 50% / 75% / 100%` 训练 mixture groups；不得每个比例重新随机抽样。
7. 增量信息同时报告新增时间窗、采样点和新增模态的 `Delta I` 与 `Delta I / Delta cost`。
8. 固定精度达标点必须在 P3 运行前冻结；未授权的门值保留 `pending_authorization`，不能填默认数。

**验收：** 同一方法重复计时可配对；数据子集严格嵌套；精度非劣与效率优越的联合 verdict 可由字段直接计算；没有单次计时结论。

**verdict：** `protocol_frozen` 或 `revise`。

### P2-09 · pilot 数据契约

**输入：** P2-03、P2-06、P2-08。

**允许修改：** 规格书“数据契约”；新子工程 schema、manifest、ID、split 和 validation 测试。仍禁止生成 pilot 数据。

**操作：**

1. 冻结 `mixture_id`、`sequence_id`、组成、nuisance、档位、模态 profile、单位和来源字段。
2. 冻结数组层：Raw waveform、slow channels、DSP features、labels、样本级 Fisher、有效 Fisher、CRB、CRB P90、主夹角、增量信息。
3. 冻结 solver difficulty 长表键：`sequence_id + method_id + split_id + seed`；字段至少含 P2-08 第 5 项。
4. manifest 明确 `primary_key=mixture_id`、`instance_key=sequence_id`、`split_group_field=mixture_id`、schema version 和每个文件 SHA256。
5. DSP 作为 Raw 的派生产物，必须保存源 Raw manifest hash、DSP 配置 hash 和代码 hash；配置不匹配时失败，不得静默复用缓存。
6. oracle 字段放在独立审计层，不得出现在部署 dataset loader 的允许字段中。
7. split validation 必须证明同一 `mixture_id` 不跨 train/val/test；不得依赖历史噪声种子字段。

**验收命令：**

以下命令的 `workdir` 必须设置为 `gas_information_bench/`：

```powershell
python -m pytest -q
rg -n "base_condition_id|noise_seed_index|noise_seed" .
rg -n "from (hg|sg|tv3|rcdw)|import (hg|sg|tv3|rcdw)" .
```

测试必须从新子工程根目录运行。两个 `rg` 命令应为零命中；若测试文本必须核查禁用字段，命中只能位于显式 rejection test。

**verdict：** `contract_frozen` 或 `revise`。

### P2-10 · S5 物理来源与 model discrepancy 接口

**输入：** P2-04 参数表、P2-05 前向实现、现有参考文档与器件手册。

**允许修改：** 规格书 S5、来源 registry、discrepancy 接口契约和纯接口测试。

**操作：**

1. 每个物理常数、噪声模型、频响和工作范围登记来源类型、引用、页码或表号、单位和适用范围。
2. 将来源分为同行评议、器件手册、工程假设；工程假设不得伪装成已验证常数。
3. 设计 `delta(observation, condition, modality, discrepancy_profile)` 接口；默认 profile 必须是显式 `off`。
4. discrepancy 只预留给 P5 sim-to-real 评估；P2 不用自注入偏差证明 C3 有效。
5. 缺少关键来源时 verdict 为 blocked，不得用相邻场景的数值静默替代。

**验收：** 每个进入前向方程的量都能追溯；单位转换有测试；`off` 时前向输出逐元素不变。

**verdict：** `source_complete` 或 `blocked_source_missing`。

### P2-11 · S6 工程归属与冻结纪律

**输入：** P2-01、P2-03、P2-09；总体规划 §6.6、§11。

**允许修改：** 规格书 S6、新子工程骨架与契约测试、根 `README.md` 的结构表。不得修改历史子工程来适配新包。

**操作：**

5. 历史场景只作为迁移出处，不作为运行时依赖。

**验收：** 新子工程可独立安装与收集测试；根 README 只增加新入口，不重写历史事实；跨包 import 为零。

**verdict：** `ownership_frozen` 或 `revise`。

### P2-12 · 将候选映射到 P3 G3-4

**前置硬门：** P2-02 必须为 `authorized`；否则本任务禁止执行。

**输入：** 已授权修订、P2-06 至 P2-09、算法调研 §3 与 §5。

**允许修改：** 规格书“P3 晋级矩阵”。

**操作：**

1. C1 只提供信息谱分层和报告，不占候选行。
2. C2 为主候选：先比较 Joint LM、Classical VP、VPLR、TSVD/Ridge-VP；普通 VP 有 headroom 后才允许 IC-RDU-VP。
3. C5 先做低成本项：FO-MPLSELM 和 CRB 自适应采样。CR-PKD 只有 raw teacher 显著优于 DSP 强基线才可测试；FIGS 只有至少两个 solver 在不同信息区域分别占优才可测试。
4. C4 只有 P2-07 给出 `eligible_for_P3_test` 才进入矩阵。
5. C3 固定为 `deferred_to_P5`。
6. 每行完整写：机制、对照、所需 3 × 3 单元、primary/secondary endpoint、门值、负对照、停止条件、通过后的唯一下一步。

**验收：** 每个候选都有廉价前置；任何失败都有停止路径；没有“先做完整模型再看”；至少一个已授权算法候选可被 G3-4 判定。

**verdict：** `matrix_ready` 或 `revise`。

### P2-13 · 汇编规格书与一致性检查

**输入：** P2-01 至 P2-12 的全部 `pass/approved/authorized/frozen/ready` 产物。

**允许修改：** `docs/p2/P2_bench规格书.md`、由冻结产物自动生成的数值表。禁止修改上游结果来消除矛盾。

**操作：**

1. 按 S1–S6 顺序汇编，不按代码模块写。
2. 将原则、当前 profile、字段 schema、指标 registry、候选矩阵分开。
3. 检查术语只保留一个规范名称；尤其检查 `mixture_id`、信息档、共线档、oracle、测量级和强基线。
4. 从纯前向冻结产物自动生成 3 × 3 Fisher/CRB/angle 表，文档只引用生成结果。
5. 搜索旧字段、旧前缀、C1 “首次”、C3 晋级、未授权 C5 和跨场景 import。
6. 对 G3-1 至 G3-5 各走一遍 pass/fail 路径，确认 verdict 可达。

**验收：** S1–S6 完整；所有内部链接可打开；数值可追溯到产物 hash；禁止词检查无错误命中；没有悬空 `TODO/TBD`。

**verdict：** `ready_for_review` 或 `revise`。

### P2-14 · 设计评审与 P2 关闭

**输入：** 完整 P2 交付物、纯前向冻结产物和测试记录。

**允许修改：** `docs/p2/P2设计评审记录.md`、`docs/p2/README.md` 状态；评审提出修改时回到对应源文件，不在评审记录中叠补丁。

**评审清单：**

1. S1：信息与夹角两个轴独立，9 格可达，每格有预期 CRB。
2. S2：四组分的四项模态分工有数值证据。
3. S3：三个 headroom 开关可单独关闭。
4. S4：双标尺、四类参照、多 split、多 seed 和效率复测完整。
5. S5：常数、噪声、频响和工作域可追溯；discrepancy 默认关闭。
6. S6：新命名空间、单一所有者、append-only freeze、无私有跨包导入。
7. 数据：样本级 Fisher/CRB、增量信息、solver difficulty、Raw + DSP 完整。
8. 候选：C1 不占 G3-4，C2/C5 已授权，C4 有前置，C3 延至 P5。
9. 边界：未生成 pilot、未训练、未声称算法优势。

**verdict：** 只能是 `pass`、`revise` 或 `reject`。

- `pass`：P2 关闭，允许启动 P3 G3-1。
- `revise`：逐条指回 P2-04 至 P2-13 的源任务，修正后重新完整评审。
- `reject`：记录根因与适用范围，返回总体规划重新设计，不启动 P3。

## 7. P2 最终交接格式

P2-14 为 `pass` 后，只输出以下六项：

1. P2 verdict 与日期。
2. 规格书、复用审计、候选修订、评审记录的路径与 SHA256。
3. 新子工程身份：目录、包名、schema、ID 前缀。
4. 3 × 3 刻度的配置 ID 与 CRB/angle 产物路径。
5. 允许进入 P3 的第一个动作，只能是 G3-1 物理前向单测与负对照。
6. 风险或未通过项；P2 `pass` 时该项必须为空数组，不得用散文弱化未完成事项。

不得在交接中附带“顺便训练”“先跑一个模型看看”或直接进入 G3-4 的命令。
