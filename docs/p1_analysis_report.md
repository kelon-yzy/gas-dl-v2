## 失败原因分析

### 1. 严重过拟合 (主因)

**证据**:
- Test R² = -0.3360 < 0，模型在测试集上完全失效
- 参数量从 73K 增至 290K (4倍)，但数据量仅 ~4000 样本
- **参数/样本比** 从 0.018 激增至 0.073 (增加 4×)

**过拟合指标**:
- 模型容量远超数据复杂度，记住训练数据的噪声而非学习泛化模式
- Dropout 从 0.25 提升至 0.30 的正则化不足以抵消容量爆炸

### 2. 容量过剩与数据量不匹配

**问题**:
- 当前数据集 ~4000 样本，支撑 73K 参数已接近极限
- 290K 参数需要 **至少 15,000+ 样本** 才能有效训练
- 容量扩张倍数 (4×) >> 数据增长倍数 (0×)

**经验法则**:
- 深度学习模型通常需要 **样本数 > 参数数 × 10~50**
- P0-B: 4000 / 73K ≈ 0.055 (已偏低)
- P1: 4000 / 290K ≈ 0.014 (严重不足)

### 3. Dropout 提升不足

**当前配置**:
- Dropout 仅从 0.25 → 0.30 (提升 20%)
- 容量增加 4× 需要 **更激进的正则化** (dropout ≥ 0.40~0.50)

**建议**:
- 如果坚持 290K 参数，dropout 应至少 0.45
- 或引入更强正则化: L2 weight decay, DropConnect, 数据增强

### 4. 训练曲线分析 (需确认)

从 validation history 观察:
- Epoch 1: val R² = -4.76 (随机初始化)
- Epoch 22: val R² = -0.29 (最佳)
- Epoch 80: val R² = ? (可能继续退化)

**疑点**:
- 最佳 val R² 仍为负值，说明训练从未收敛到合理解
- 可能存在训练不稳定或梯度消失/爆炸

- "显存不足概率低" → **正确**: 确实没 OOM，但性能崩溃

## 经验教训

### ✅ 做对的

1. 保持了其他配置不变 (权重、seed、训练参数)，隔离了 TCN 容量变化的影响
2. Dry-run 验证配置正确性
3. 完整记录实验配置和结果

### ❌ 做错的

1. **低估了数据量瓶颈**: 4000 样本支撑 290K 参数严重不足
2. **过度依赖 dropout**: 0.30 dropout 对 4× 容量扩张远远不够
3. **未做中间步骤验证**: 应先尝试 [96,96,96] 再跳至 [128,128,128]
4. **未提前设置早停**: 应在 val R² 持续为负时提前终止

### 📚 技术认知更新

1. **容量扩张 ≠ 性能提升**: 小数据集下，容量扩张会导致过拟合而非泛化
2. **参数/样本比** 是关键指标: 比值 < 0.02 时容量扩张高风险
3. **Dropout 缩放规则**: 容量扩张 N× 需要 dropout 提升 √N× (例如 4× → 2×)
4. **数据增强优先于架构改进**: 在样本有限时，增加有效数据量比增加模型容量更有效
