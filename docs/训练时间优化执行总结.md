# 训练时间优化执行总结

## 状态

本文档是历史总结，不再作为当前执行方案。当前方案见 `docs/训练配置优化方案.md`。

## 当前目标服务器

| 资源 | 配置 |
|---|---|
| GPU | NVIDIA RTX5880, 48 GiB 显存 |
| CPU | AMD vCPU, 32 核 |
| 内存 | 64 GB |

## 已确认事实

- PhaseWindowTCN 三窗口输入会显著放大激活显存。
- 旧配置的 `epochs=300` 和 `early_stopping.patience=25` 对诊断批过长，已改为 `epochs=80`、`patience=10`。
- `num_workers=8`、`persistent_workers=true` 不再作为默认训练口径；当前基线为 `num_workers=2`、`persistent_workers=false`。
- `batch_size=32` 在旧 24 GiB 环境出现 OOM，不能作为无条件推荐。
- 新 48 GiB 服务器可以重新测试 `batch_size=24/32`，但必须按完整指标验收。

## 已完成的代码级改动

- `performance.tf32=true` 时同步启用 `torch.set_float32_matmul_precision("high")`。
- `Trainer.evaluate()` 和 `Trainer.predict()` 使用 `torch.inference_mode()`。

## 当前推荐执行顺序

1. 用当前基线跑 Phase 1，形成真实速度和显存表。
2. 在新服务器上做 `num_workers=0/2/4/8` sweep。
3. 单 run 试 `torch.compile(mode="reduce-overhead")`。
4. 按 `batch_size=20 -> 24 -> 32` 逐步上探。
5. 只有速度、显存、`val_loss`、`test/extrapolation x_N2 R2` 全部通过，才把候选写入正式配置。

## 废弃预期

以下历史估算已废弃：

- 显存必然从 `17GB` 降到 `6-8GB`。
- `batch_size=32` 必然比 16 更快且可运行。
- Phase 1 + Phase 2 必然压缩到 `2.5-3.5 小时`。
