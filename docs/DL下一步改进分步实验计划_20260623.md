# DL 下一步改进分步实验计划

日期：2026-06-23

状态：待执行

适用数据：`data/wv4-formal-hitran-standard-6000`

当前结论：`head` 参数化和输入契约两条线已收束。下一步不再继续调 `gas_head` / `softmax100` / raw int16，而是围绕 `raw4 + dequantized_scale5` 做特征提取与融合结构验证。

## 0. 今日实验依据

### 0.1 `n2_head_sweep`

| -------------------------------- | ------------ | ---------------:| ----------:| ------------------- |

### 0.2 `n2_input_contract_ablation`

| ------------------------------------------ | ---------------------- | ---------------:| ----------:| ------------------:| -------- |
| `phase_window_tcn_raw4_int16`              | raw int16              | -0.5610         | -0.1837    | 25.4844            | 不作为默认输入  |
| `phase_window_tcn_raw4_dequantized_scale5` | dequantized, scale=5.0 | -0.3052         | -0.1915    | 20.5156            | 当前最佳输入契约 |

### 0.3 参照基线

历史 `cnn1d_tcn_fusion` 在 `formal_full` 中 test overall R2 约 0.7138，但 N2 R2 仍接近 0。历史 `ridge_all_modalities` test overall R2 约 0.7968，`ridge_alr_ch4_all_modalities` test overall R2 约 0.7123。`phaseaware_best_models` 中 `cnn1d_tcn_fusion_early_075` test overall R2 约 0.7228。

因此，下一步的核心问题不是“DL 是否能降低 loss”，而是：

1. 能否把历史强整体 backbone 与 `raw4 + dequantized_scale5` 契约合并。
2. 能否让多窗口之间发生真实交互，而不是仅在 MLP 前拼接。
3. 能否在小实验矩阵内判断是否值得继续投入 DL。
4. 能否用统一指标门槛避免单次波动误判。

## 1. 优先级 1：把历史强 baseline 改成 `raw4 + dequantized_scale5`

### 1.1 目标

验证“强整体特征提取 + N2 独立参数 + 反量化输入”是否能同时恢复 overall R2 和 N2 R2。

这是最高优先级，因为历史 `cnn1d_tcn_fusion` 的整体特征能力显著强于当前 `PhaseWindowTCN`，而今天的实验已经证明 `raw4` 是必要输出契约、`dequantized_scale5` 是更优输入契约。

### 1.2 关键假设

如果瓶颈主要是 `PhaseWindowTCN` 的特征提取和窗口融合，那么把 `cnn1d_tcn_fusion` 改成 `raw4 + dequantized_scale5` 应至少恢复 overall R2 到 0.6 以上，并使 N2 R2 明显高于 0。

如果 overall R2 恢复但 N2 仍接近 0，说明 backbone 强度够，但 N2 仍需要组件级目标或损失处理。

### 1.3 代码改动

影响文件：

- `src/dl/models/cnn1d_tcn_fusion.py`
- `src/dl/models/registry.py` 如需新增模型名
- `tests/test_dl_models.py`
- `configs/experiment/<new_experiment>/...json`

推荐做法：

1. 保留现有 `CNN1DTCNFusionRegressor` 的 `gas_head` 行为，避免破坏历史配置。
2. 增加 `output_mode` 参数，取值至少支持 `gas_head` 和 `raw4`。
3. 当 `output_mode="raw4"` 时，使用 `nn.Linear(h2, out_dim)` 作为输出头。
4. 允许 `waveform_int16_scale=5.0` 与 `dequantize_waveforms=true` 组合。
5. 不引入闭包 fallback，不把 `mixture_id` 回退或重写为 `sequence_id`。

### 1.4 实验配置

建议新建：

`configs/experiment/dl_feature_upgrade/dl_feature_upgrade_stage1.json`

包含两个 run，同 seed 同训练口径：

| run                                        | model              | output mode | input                 | 目的     |
| ------------------------------------------ | ------------------ | ----------- | --------------------- | ------ |
| `cnn1d_tcn_fusion_gas_dequantized_scale5`  | `cnn1d_tcn_fusion` | `gas_head`  | dequantized scale=5.0 | 分离输入收益 |
| `cnn1d_tcn_fusion_raw4_dequantized_scale5` | `cnn1d_tcn_fusion` | `raw4`      | dequantized scale=5.0 | 主候选    |

建议训练参数：

3. 本地运行目标测试：

4. 服务器 dry-run：

5. 服务器实跑：

### 1.6 判据

通过条件：

- `cnn1d_tcn_fusion_raw4_dequantized_scale5` test overall R2 >= 0.6。
- test N2 R2 > 0。
- extrapolation N2 R2 > 0。
- H2 / CH4 / CO2 不出现系统性退化。

强通过条件：

- test overall R2 >= 0.7。
- test N2 R2 >= 0.2。
- extrapolation N2 R2 >= 0.2。

停止条件：

- overall R2 仍小于 0.3，说明 raw4 破坏了 `cnn1d_tcn_fusion` 的整体拟合，应先查训练曲线与输出尺度。
- N2 R2 仍为负但 overall R2 恢复到 0.7 左右，进入组件级 N2 诊断，不急着换 backbone。

## 2. 优先级 2：重做 phase/window 融合方式

### 2.1 目标

验证 `PhaseWindowTCN` 的主要失败是否来自“三个窗口各自编码后直接 concat”的融合方式。

当前 `PhaseWindowTCN` 的窗口间关系由 MLP 间接学习，没有显式窗口 token、窗口级 attention 或相位交互。这个结构可能丢掉 full / exposure / recovery 的互补关系。

### 2.2 关键假设

如果窗口间交互是瓶颈，那么在保持 `raw4 + dequantized_scale5` 不变时，引入轻量窗口 attention 应优于单纯加宽 CNN 或加深 TCN。

### 2.3 实验分组

建议新建：

`configs/experiment/dl_feature_upgrade/dl_feature_upgrade_stage2.json`

包含三个 run：

| run                                                         | 改动                                  | 目的              |
| ----------------------------------------------------------- | ----------------------------------- | --------------- |
| `phase_window_tcn_raw4_dequantized_scale5_baseline`         | 复跑当前最佳 `PhaseWindowTCN`             | 建立同批基线          |
| `phase_window_tcn_raw4_dequantized_scale5_wide_acoustic`    | `acoustic_channels=[32,64,128,128]` | 验证声学 encoder 容量 |
| `phase_window_tcn_raw4_dequantized_scale5_window_attention` | 窗口级 attention 替代 concat-only        | 验证窗口交互          |

### 2.4 推荐实现路径

先实现轻量窗口 attention，不直接上完整 transformer。

结构建议：

```text
z_full, z_exposure, z_recovery = window_encoder(...)
Z = stack([z_full, z_exposure, z_recovery])        # B, 3, D
Z = Linear(D -> fusion_dim)
Z = TransformerEncoder(num_layers=1, nhead=4)
pooled = attention_pool(Z) 或 mean(Z)
out = MLP(pooled) -> raw4
```

代码位置建议：

- 新模型文件：`src/dl/models/phase_window_attention.py`
- 注册名：`phase_window_attention`
- 单测：`tests/test_dl_models.py`

### 2.5 执行步骤

1. 先复制 `PhaseWindowTCNRegressor` 的输入契约与窗口读取逻辑，不改数据管线。
2. 将每个窗口编码后的向量作为 3 个 token。
3. 增加 1 层 `nn.TransformerEncoder` 或 `nn.MultiheadAttention`。
4. 输出只支持 `raw4`，暂不支持 `gas_head` 和 `softmax100`。
5. 跑目标测试：

```text
python -m pytest tests/test_dl_models.py tests/test_run_experiment.py -q
```

6. 服务器 dry-run 和实跑：

```text
python -m pipeline.run_experiment --config configs/experiment/dl_feature_upgrade/dl_feature_upgrade_stage2.json --dry-run
python -m pipeline.run_experiment --config configs/experiment/dl_feature_upgrade/dl_feature_upgrade_stage2.json
```

### 2.6 判据

若 `window_attention` 明显优于同批 baseline：

- test overall R2 至少提升 0.2。
- test 与 extrapolation N2 R2 同时提升。
- best epoch 不显著提前，val loss 不更早崩。

若 `wide_acoustic` 有效而 `window_attention` 无效：

- 下一步转向声学 encoder 容量与正则。

若 `window_attention` 有效而 `wide_acoustic` 无效：

- 下一步转向窗口交互，不继续堆 CNN。

若两者都无效：

- `PhaseWindowTCN` 路线降级；优先回到优先级 1 的 `cnn1d_tcn_fusion_raw4_dequantized_scale5`。

## 3. 优先级 3：小矩阵验证，不一次铺大

### 3.1 目标

用最小实验矩阵判断方向是否成立，避免同时引入多个新变量导致无法归因。

### 3.2 最小矩阵

第一批只跑 3 个主实验：

| 优先级 | run                                                      | 变量                 | 预期回答           |
| ---:| -------------------------------------------------------- | ------------------ | -------------- |
| 1   | `cnn1d_tcn_fusion_raw4_dequantized_scale5`               | 强历史 backbone + 新契约 | 历史强整体模型能否救回 N2 |
| 2   | `phase_window_tcn_raw4_dequantized_scale5_wide_acoustic` | 加宽声学 encoder       | 声学特征容量是否不足     |
| 3   | `phase_window_attention_raw4_dequantized_scale5`         | 窗口 attention       | 窗口交互是否是瓶颈      |

### 3.3 执行顺序

1. 先做优先级 1。它改动最小，信息量最高。
2. 若优先级 1 通过或强通过，再做优先级 2 的 `window_attention`，判断是否能进一步补 N2。
3. 若优先级 1 不通过但训练曲线正常，再做 `wide_acoustic`，确认是不是原始波形特征仍学不到。
4. 若优先级 1 不通过且训练曲线异常，先修训练稳定性，不进入新结构。

### 3.4 不纳入首批的内容

以下内容暂缓：

- 多层大 Transformer。
- DCT / 频率解耦 attention。
- component-aware gated fusion。
- GradNorm 或不确定性动态加权。
- 多 seed 大规模验证。

这些内容只有在小矩阵出现正信号后再做，否则会制造更多不可解释变量。

## 4. 优先级 4：统一指标、门槛和归档

### 4.1 必看指标

每个 run 必须记录并比较：

- val / test / extrapolation overall R2。
- val / test / extrapolation N2 R2。
- H2 / CH4 / CO2 / N2 per-component R2。
- MAE、RMSE。
- `sum_abs_error`。
- `best_epoch`。
- train / val loss 曲线。

### 4.2 成功门槛

最低有效：

- test overall R2 > 0。
- test N2 R2 > 0。
- extrapolation N2 R2 > 0。

可继续投入：

- test overall R2 >= 0.6。
- test N2 R2 >= 0.1。
- extrapolation N2 R2 >= 0.1。

强信号：

- test overall R2 >= 0.7。
- test N2 R2 >= 0.2。
- extrapolation N2 R2 >= 0.2。

接近正式可竞争：

- test overall R2 接近或超过 0.8。
- test N2 R2 接近或超过 0.5。
- extrapolation 不明显掉线。

### 4.3 失败判据

任一情况应停止该分支：

- test 与 extrapolation N2 R2 同时为负。
- overall R2 相比同批 baseline 下降超过 0.2。
- H2 / CH4 / CO2 三组分系统性下降。
- best epoch 过早且 train loss 继续下降、val loss 回升，说明增容导致过拟合。
- `sum_abs_error` 大幅扩大且没有解释。

### 4.4 归档要求

每批实验结束后保留：

- `outputs/summary/<experiment>_summary.csv`
- `outputs/reports/<experiment>.md`
- 每个 run 的 `run_config.json`
- 每个 run 的 `metrics.json`
- 每个 run 的 `metrics_live.jsonl`
- 决策说明：继续、切换、停止的原因

建议归档目录：

```text
outputs/archive/dl_feature_upgrade_<YYYYMMDD>/
```

### 4.5 同批比较规则

- 同一批实验必须同 seed。
- 不把历史 run 与新 run 当作严格同批对照，只作为参照。
- Ridge 是外部强基准，用于判断差距，不用于同 seed 严格比较。
- 如果单个 run 看起来有效，下一步先做 multi-seed 验证，不立即改默认主线。

2. 新增 `phase_window_attention` 最小模型骨架，若时间有限可放到 Step C。
3. 新增 `configs/experiment/dl_feature_upgrade/`。
4. 跑本地目标测试。

### Step B：先跑最高信息量实验

运行：


- 若 `cnn1d_tcn_fusion_raw4_dequantized_scale5` 达到可继续投入门槛，则它成为新 DL 候选基线。
- 若 overall 高但 N2 低，保留它为强 backbone，后续做 N2 专门诊断。

## 6. 最终决策树

```text
Stage 1: cnn1d_tcn_fusion_raw4_dequantized_scale5
├─ overall >= 0.7 且 N2 > 0
│  └─ 设为新 DL 候选基线，做 multi-seed
├─ overall >= 0.7 但 N2 <= 0
│  └─ backbone 有效，转 N2 专门损失 / 目标诊断
└─ overall < 0.3
   └─ 不急着换结构，先查训练曲线、输出尺度和 loss

Stage 2: PhaseWindow attention / wide acoustic
├─ window_attention 有效
│  └─ 继续窗口交互路线
├─ wide_acoustic 有效
│  └─ 继续声学 encoder 容量路线
└─ 两者都无效
   └─ 停止 PhaseWindowTCN 扩展，保留负结果

Stage 3: multi-seed
├─ 稳定有效
│  └─ 写入新 DL 主线候选
└─ 不稳定
   └─ 记录为单次正信号，不提升为默认路线
```

## 7. 当前建议

下一次实际编码应从优先级 1 开始：

1. 给 `cnn1d_tcn_fusion` 增加 `raw4` 输出模式。
2. 新建 `dl_feature_upgrade_stage1.json`。
3. 跑 `cnn1d_tcn_fusion_raw4_dequantized_scale5`。
4. 只有它给出正信号后，再投入 `phase_window_attention`。

这一路线的好处是变量最少：先把已知有效的历史 backbone 和今天确认有效的新契约合并，避免在明显较弱的 `PhaseWindowTCN` 上继续叠复杂结构。
