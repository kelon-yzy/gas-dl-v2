# 3. 测量级信号处理

## 3.1 为什么需要这一层

合成研究可以直接读取模拟器内部的物理量，但由此得到的下游结果依赖不可部署的真值状态，不能直接代表真实仪器能力。

因此，本层丢弃这些数组，使用固定的信号处理链从存储的原始波形重新估计每个物理量；该链不包含任何真值量。它有两个目的：定义一条可部署链实际会计算什么，并使第 6.3 节的同等性检查具有意义。基于这些特征的线性基线达到与基于模拟器数组的基线相同的精度，因而允许将本研究其余部分理解为关于测量的陈述，而不是关于模拟的陈述。

使用该层的特征构建器显式拒绝读取六个模拟器真值数组；一旦被要求读取便会失败，而不是降级运行。

## 3.2 模板标定

匹配滤波模板**只由训练分区**的基线相位帧估计；不使用精确模拟器模板，且至少需要四个可用基线帧，否则该序列会显式失败。

对于每个合格帧，流程先在 Hilbert 包络上定位粗略峰值，在半载波周期半径内锁定符号正确的采样点，随后围绕它提取固定长度片段，去均值并按峰值归一化。模板取所有片段的**逐点中位数**，并统一极性。

选择中位数而非均值是有意为之：少量存在周期滑移的帧会拖偏均值模板，而受损模板会以难以在下游发现的方式劣化后续所有估计。

## 3.3 帧级飞行时间估计

每帧执行四步。

**物理搜索窗口。** 边界由声速和延迟限制给出：

```
t_lo = L / c_max + δ_min ,        t_hi = L / c_min + δ_max ,
```

其中 `c ∈ [250, 400]` m/s，`δ ∈ [40, 130]` μs。窗口之外的相关峰不参与竞争。这是四项保护中代价最低的一项，能够排除最大一类粗大错误。

**归一化互相关。** 对去均值后的模板在帧上滑动，分母由累积和差分得到的逐窗口局部能量构成。归一化到 `[−1, 1]` 后，相关峰值可直接作为形状一致性指标，第 3.4 节将利用它。

**包络锁定的峰值选择。** 首先通过 Hilbert 包络定位主瓣，然后只在其半载波周期半径内取相关最大值。两者单独使用都不够：在 200 kHz 载频下，全局 `argmax` 会选错周期；仅用包络峰则没有相位精度。

**抛物线亚采样插值。** 三点抛物线给出分数偏移，限制在 `[−0.5, 0.5]`，峰值也以相同阶次进行校正。

## 3.4 帧质量指标

每帧输出六个可部署指标，均不使用真值量：相关峰、峰旁瓣比（排除主峰周围 8 个采样点）、信噪比、相关峰半宽、峰值电压，以及削顶和边界标志。

信噪比使用物理搜索窗口外样本得到的**稳健噪声估计**：

```
SNR_dB = 20 log10 ( max |w| inside window / (1.4826 · MAD(w outside window)) ).
```

**该特征是本研究中贡献最大的单项特征。** 第 6.5.1 节的增量探针显示，标定量、校正飞行时间、飞行时间对声程的斜率和声速合计只能达到 `R²` 0.13–0.21；加入信噪比数组后，结果越过同等性门槛。其原因在于信噪比携带了与时序信息互补的衰减信息，而非仅对时序估计进行细化。

帧接受条件是六个条件的合取：相关峰 ≥ 0.50、峰旁瓣比 ≥ 1.10、SNR ≥ 10 dB、峰宽 ≤ 12 个采样点、未削顶且未接触边界。同时还输出连续质量分数，它将三个分量相乘，并对每项削顶或边界接触减半。

> 在这里所用的干净合成设定中，几乎所有帧都被接受。这本身是一个具有后果的发现：由于帧质量不存在异质性，质量感知门控和注意力模块在整个研究中始终关闭，因为它们没有可学习的内容。这一限制不应迁移到真实测量。

## 3.5 序列级标定与声速估计

在帧级结果之上执行两项操作。

**延迟标定。** 仅使用基线窗口中的接受帧，在当前温度、压力和湿度下计算新鲜空气的参考声速（0.04 / 20.90 / 79.06 vol %），并把延迟定义为残差中位数：

```
δ̂ = median( τ_obs − L / c_fresh ) ,     τ_corr = τ_obs − δ̂ .
```

这会吸收 82 μs 系统延迟和设备间变异，并依赖一个现场部署可以满足的假设：基线窗口包含新鲜空气。

**多声程声速回归。** 仅使用稳态窗口中的接受帧，对 `τ_obs` 关于 `L` 进行 **Theil–Sen** 回归：

```
τ_obs = a + b L ,        ĉ = 1 / b ,
```

斜率给出声速，截距给出独立于声速的延迟估计。选择 Theil–Sen 而非最小二乘，是因为偶发的周期滑移会产生最小二乘斜率无法承受的离群点。还存在一个以 SNR 加权的闭式最小二乘消融版本；其测得增益约为 +0.0006，因而未被提升为正式方法。

## 3.6 特征聚合

每条通道的时间序列沿三个轴扩展：九种统计量（均值、标准差、最小值、最大值、极差、首值、末值、差值、斜率）、八个窗口（完整序列、四个相位窗口及 25 %、50 %、75 % 三个早期比例窗口），以及通道集合本身。

| 构建器 | 通道 | 维度 |
| --- | --- | ---: |
| observed | 7 条慢速 + 5 个观测物理数组 | 12 × 9 × 8 = **864** |
| RawDSP | 7 条慢速 + 7 个 RawDSP 数组 | 14 × 9 × 8 = **1008** |

第 6.5.1 节的增量探针另用一种更紧凑的序列表示：在五个窗口上使用七种统计量，故每个数组有 35 列；这也解释了为何其中增加一个数组会使维度恰好增加 35。

## 3.7 命名纪律

**改变构建器的输出必须使用新的构建器名称。** 在已有名称下重定义构建器输出会被拒绝；冻结脚本还会验证配置中记录的构建器名称与其产生的指标中记录的名称一致。

这项规则用于确保“哪个特征产生了这个数值”这个问题在时间推移后仍有答案。它也使第 7.3 节的一项更正得以发现：两个配置声明了不同构建器名称，却定义了相同特征集合；命名约定本身不能阻止此事，但比较声明后会立即暴露它。
